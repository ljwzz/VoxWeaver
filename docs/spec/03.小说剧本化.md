# 阶段 03：小说剧本化

状态：`planned`
实现审计：`unverified`
前置阶段：[01 小说导入与文件预处理](./01.小说导入与文件预处理.md)、[02 文本校对](./02.文本校对.md)

## 1. 目标

把 corrected 文本转换为适合审核、角色解析和 TTS 的结构化剧本。转换不得改变小说内容，必须保留原文定位和不确定项。

## 2. 范围

- 旁白、对白、内心独白、群体发言、引用/转述和未知类型；
- 动作、情绪、身体状态、表达方式和停顿候选；
- 说话人提及、别名和身份候选；
- `ScriptUnit` 稳定 ID、源范围和上下文；
- 与阶段 04 的角色归并迭代；
- 人工编辑、审核、版本和增量过期。

## 3. 非目标

- 不在本阶段建立最终 Character Registry；
- 不强制猜测未知说话人；
- 不分配最终音色；
- 不生成发音、音频或最终时间轴；
- 不把 `ProcessingSegment` 当作 ScriptUnit。

## 4. 两遍处理

严格线性“先剧本、后角色”无法同时解决别名归并和说话人解析，因此采用两遍迭代：

```text
第一遍：结构抽取
corrected text
→ 叙述类型、对白边界、动作、说话人提及和证据

阶段 04：角色归并
说话人提及和全书实体
→ Character / Alias / Stage

第二遍：说话人解析
ScriptUnit 候选 + Character Registry
→ speaker_id、置信度、冲突和人工队列
```

角色归并变化可以再次触发第二遍，但不得重新切分无关 ScriptUnit。

## 5. ScriptUnit

```ts
interface ScriptUnit {
  scriptUnitId: string;
  chapterId: string;
  sceneId: string;
  order: number;
  sourceRange: TextRange;
  type: "narration" | "dialogue" | "inner_monologue" | "group" | "quotation" | "unknown";
  text: string;
  speakerMention?: string;
  speakerId?: string;
  speakerConfidence?: number;
  characterStageId?: string;
  emotion?: EmotionCandidate;
  physicalState?: PhysicalStateCandidate;
  speechStyle?: SpeechStyleCandidate;
  pauseAfterMs?: number;
  evidence: EvidenceRef[];
  reviewStatus: "pending" | "approved" | "rejected";
}
```

`script_unit_id` 不得由当前顺序或文本明文直接充当唯一身份。顺序改变时，未变化单元应尽可能稳定对齐。

## 6. 说话人判断

第一遍提取：

- 引号和对话边界；
- “某人说道”等关联动作；
- 连续对话轮次；
- 称谓和代词；
- 场景内人物候选；
- 传音、回忆、梦境、嵌套转述和引用证据。

第二遍校验：

- 角色是否在场；
- 别名是否属于同一角色；
- 首次出场和人物时间范围；
- 连续轮次是否合理；
- 自动结论是否与人工锁定冲突。

无法可靠判断时必须使用 `unknown` 并进入审核，不得为了满足 schema 随机选择角色。

## 7. 情绪、身体状态和表达方式

这些字段属于当前 ScriptUnit 的瞬时表现，不得直接改写角色永久档案。候选至少记录来源、置信度和证据；人工锁定优先于自动建议。

角色长期年龄/剧情阶段由阶段 04 的 `CharacterStage` 表达，当前单元只引用有效的 stage，并可叠加瞬时情绪、受伤、虚弱、耳语、战斗或内心独白等表现。

## 8. 页面和审核

剧本编辑器必须支持：

- corrected 原文与 ScriptUnit 对照；
- 按 Scene 查看旁白和对白顺序；
- 修改类型、说话人、情绪、身体状态、表达方式、语速、音量和停顿；
- 查看模型证据和角色归并依据；
- 批量处理 `unknown` 和低置信度项；
- 预览修改对发音、音色、音频、QA 和章节合成的影响；
- 比较历史剧本 revision。

## 9. 版本和过期影响

- ScriptUnit 文本变化：spoken、片段音频、QA、章节合成和导出过期；
- 类型或说话人变化：声音选择、片段音频及其消费者过期；
- 情绪、身体状态、表达方式或停顿变化：实际依赖字段的音频/合成消费者过期；
- 仅审核备注变化：音频不应过期；
- 角色 Alias 归并变化：只重新解析命中的 ScriptUnit；
- Scene 边界变化：相交 ScriptUnit 重新切分，其他单元保持稳定。

## 10. 早期实现迁移

重点检查：

- 是否把整个处理 Segment 当作一句台词；
- 是否丢失 corrected 原文范围；
- 是否把 speaker 文本名称直接当作 Character ID；
- 是否强制填充未知说话人；
- 是否把角色长期阶段和当前情绪混成一个字段；
- 是否修改一句就重建整章音频；
- 是否把模型建议覆盖人工结论。

可复用的引号解析、对白边界和结构抽取可标记 `adapt`；无来源定位或会改写正文的实现标记 `replace`。

## 11. 测试要求

- 旁白、直接对白、内心独白、引用、转述和未知类型；
- 连续双人/多人对话；
- 传音、梦境、回忆和嵌套引号；
- 说话人证据与置信度完整；
- ScriptUnit 合并可以按明确 separator 还原 corrected 内容；
- Character Registry 更新只重新解析命中候选；
- 人工锁定不会被后台重跑覆盖；
- 单一 ScriptUnit 修改只使对应消费者过期。

## 12. 验收标准

- 所有正文被映射为 ScriptUnit 或明确未处理范围；
- 所有对白具有角色、旁白、群体或 `unknown` 状态；
- `unknown` 和阻断性低置信度项不能直接进入批量 TTS；
- 每个单元可反查 corrected 文本和源资产；
- 模型建议和人工最终决定分别保存；
- 修改一个单元不要求重建无关单元。
