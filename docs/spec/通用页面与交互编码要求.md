# 通用规格：桌面页面与交互编码要求

## 适用范围

本规格适用于已经确认的页面和后续新增的所有桌面页面。

- 阶段规格描述当前业务步骤的特有输入、处理和结果；本规格描述所有页面共同遵守的实现基线。
- 阶段规格需要偏离本规格时，必须明确记录例外范围和原因。
- 未在设计稿或规格中确认的业务规则，不得在编码时自行补充或推断。

## 设计稿与规格的职责

- Figma 设计稿用于确认页面结构、视觉层级、字段类型、操作位置和需要呈现的状态。
- 规格用于确认真实数据来源、业务状态、持久化结果、失败处理和页面跳转条件。
- 编码不能只还原静态外观；必须实现规格要求的输入、处理中、成功、失败和重试流程。
- 设计稿中的示例路径、文件名和其他示例数据仅用于展示，不得作为默认值或硬编码数据。

## 页面主任务与信息层级

- 每个页面或步骤只设置一个清晰的主任务和一个主要推进操作。
- 标题、字段、状态和操作围绕当前主任务组织，不在多个区域重复表达同一信息。
- 只保留完成当前任务所必需的说明、状态、风险和错误信息。
- 删除装饰性、重复性或不能帮助用户完成当前任务的提示。
- 未实现的后续入口可以保留，但不得伪造可用状态或跳转到空页面。

## 字段与数据语义

- 可编辑字段、系统识别结果和只读结果必须有明确区别。
- 自动识别值必须显示实际结果；允许修正的识别结果必须提供可编辑控件。
- 只读字段不得由页面提交值覆盖，后端或应用服务必须从真实输入重新计算或校验。
- 字段校验错误应靠近对应字段显示，并保留其他已经填写或选择的有效内容。
- 同一数据在不同页面使用一致的名称、单位、格式和空值表达。

## 页面状态与操作门禁

每个带提交或推进操作的页面至少覆盖以下状态：

```text
idle
ready
running
failed
succeeded
```

这些名称描述页面交互状态，不要求新增一套与领域任务状态平行的持久化枚举；实现时应明确它们与领域状态的映射。

- 主要按钮的启用条件必须覆盖当前步骤的全部必填输入和前置条件。
- 前置条件缺失、字段无效或阻塞操作执行中时，主要按钮不可重复触发。
- 点击主要按钮后进入明确的处理中状态，并锁定会影响本次执行的输入。
- 只有当前步骤要求的数据处理和持久化全部成功后，才能记录成功状态并进入下一页面。
- 页面只采集、计算和展示当前阶段规格明确要求的数据，不得因为后续阶段需要而提前执行分析或生成产物。
- 当前页面的成功状态只表示本阶段要求已经完成，不得把后续阶段产物加入当前页面的跳转门禁。
- 后续页面必须校验持久化的成功状态，不能只依赖前端按钮是否禁用。
- 返回、取消或关闭窗口不得把未完成操作标记为成功。

## 错误与重试

- 阻塞操作失败时停留在当前页面，不得进入下一步骤。
- 保留仍然有效的用户输入和系统结果，允许用户修正后重试。
- 错误信息必须说明失败对象、失败阶段和可执行的恢复动作。
- 失败不得覆盖最后一次有效结果，也不得发布不完整的中间产物。
- 重试必须具备幂等边界，不能因重复点击生成多个互相冲突的正式结果。

## Electron 与 Vue 实现边界

- Vue Renderer 负责页面展示、表单状态和用户交互，不直接执行本地文件系统写入。
- 原生文件或文件夹选择、项目目录创建、文件复制、格式转换和持久化由 Electron Main 或应用服务执行。
- BrowserWindow 保持 `contextIsolation: true` 和 `nodeIntegration: false`；Renderer 不直接获得 Node.js 权限。
- Preload 只通过 `contextBridge` 暴露当前页面需要的最小、具名、类型明确的 IPC 方法；不得向 Renderer 暴露完整 `ipcRenderer` 或通用文件系统能力。
- IPC 请求和响应必须使用共享类型定义，并覆盖成功、失败、取消和处理中状态。
- 长耗时操作需要返回进度或当前阶段；Renderer 不得通过轮询文件是否存在来判断业务成功。

实现边界参考 Electron 官方的 [进程模型](https://www.electronjs.org/docs/latest/tutorial/process-model)、[进程间通信](https://www.electronjs.org/docs/latest/tutorial/ipc)、[contextBridge](https://www.electronjs.org/docs/latest/api/context-bridge) 和 [安全指南](https://www.electronjs.org/docs/latest/tutorial/security) 文档。

## 组件与桌面一致性

- 当前页面按 macOS 桌面应用场景实现，不引入移动端页面模式。
- 优先复用 Element Plus 组件和项目级主题变量；同类字段、按钮、错误、加载和只读状态保持一致。
- 页面不得复制一套与公共组件不同的交互实现。
- 键盘焦点、禁用态、加载态和错误态必须可辨识。

## 编码验收清单

1. 页面主任务和主要推进操作是否唯一且清晰。
2. 是否只保留完成当前任务需要的信息。
3. 页面数据是否来自真实状态，而非设计稿示例值。
4. 可编辑、自动识别和只读字段是否符合规格。
5. 按钮启用条件、处理中锁定和页面跳转门禁是否完整。
6. 重复提交是否被阻止，重试是否不会产生冲突结果。
7. 失败是否停留当前页面、保留有效输入并提供恢复动作。
8. 文件系统和原生能力是否通过受限 IPC 调用。
9. 是否复用公共组件、主题和统一状态表达。
