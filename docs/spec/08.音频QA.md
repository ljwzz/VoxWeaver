# 阶段 08：音频 QA

状态：`planned`
实现审计：`unverified`
前置阶段：[07 TTS 生成](./07.TTS生成.md)
架构约束：[ADR 0001：模型能力统一通过 Provider API 接入](../../docs/adr/0001-model-capabilities-via-provider-apis.md)

## 1. 目标

通过外部 ASR Provider API 回听、文本差异、音频指标和人工审核识别片段问题，决定通过、复核、重生成或永久失败，不把单一自动指标当作最终质量结论。VoxWeaver 不运行、下载或分发 ASR、VAD 或说话人分析模型。

## 2. 范围

- ASR Provider adapter 和转写；
- 目标 spoken 与回听文本差异；
- 人名、术语、数字和单位加权检查；
- 漏读、多读、重复、异常插入和断句候选；
- 削波、超长静音、截断、响度、时长和损坏检测；
- PASS/WARNING/FAIL 策略；
- 自动重试上限和人工审核队列；
- QA revision、证据和最终结论。

## 3. 非目标

- 不以 ASR 字符差异单独判断听感；
- 不把同音转写差异直接等同于发音错误；
- 不自动无限重生成；
- 不覆盖原始生成音频；
- 不在未校准样章前固定生产阈值。

## 4. 数据模型

```ts
interface QAResult {
  qaResultId: string;
  audioArtifactId: string;
  targetSpokenRevisionId: string;
  providerProfileId?: string;
  asrAdapterId?: string;
  apiDialect?: string;
  asrModelVersion?: string;
  providerRequestId?: string;
  transcript?: string;
  textIssues: QAIssue[];
  audioIssues: QAIssue[];
  machineDecision: "pass" | "warning" | "fail";
  finalDecision: "pending" | "approved" | "rejected";
  reviewedBy?: string;
}
```

每个问题必须有类型、位置、证据、指标、阈值版本和处理建议。

## 5. 处理流程

```text
AudioClip + spoken target
→ 文件和音频基础校验
→ ASR 转写
→ 加权文本差异
→ 音频指标检查
→ 规则聚合
→ 自动通过 / 人工复核 / 有限自动重试 / 永久失败
```

候选 ASR Provider API 必须通过 adapter 声明上传格式、时间戳、语言提示、说话人标签、同步/异步任务、取消、限流和数据保留能力。

说话人 diarization Provider 只能返回时间段、匿名说话人标签和证据，不能自动确认真实角色。角色绑定仍由上下文规则和人工审核确认。

## 6. 审核策略

- 自动通过、警告、失败和重试阈值必须版本化；
- 阈值通过合法授权样章校准，记录误报和漏报；
- 人名、术语、数字和单位可以高于普通字符差异权重；
- 连续失败达到上限后进入人工队列；
- 人工可以接受机器警告、拒绝机器通过或修改问题分类；
- 重新生成必须创建新 AudioClip revision，并保留失败音频和原因。

## 7. 页面和审核

- 波形、音频、spoken、ASR 文本和差异对照；
- 按角色、章节、问题、后端和失败次数筛选；
- 单片段重生成、修改 spoken、发音、音色或表现并跳转对应阶段；
- 批量通过低风险项；
- 比较同一 ScriptUnit 多个音频和 QA；
- 查看机器结论、最终结论和全部阈值版本。

## 8. 版本和过期影响

- 新音频产生新的 QA 任务，旧 QA 保留；
- spoken 变化使对应 QA 过期，即使音频未变化；
- QA 算法或阈值版本升级不应自动抹去旧结论；是否重评由策略激活；
- 仅修改审核备注不使音频或章节过期；
- 最终审核从批准变为拒绝时，引用该片段的章节合成和导出过期；
- 修复发音或音色问题通过对应阶段产生新版本，不直接改 QA 结果。

## 9. 早期实现迁移

检查旧实现是否：

- 只比较 ASR 字符串；
- 使用硬编码阈值；
- 自动重试无上限；
- 失败时覆盖旧音频；
- 无机器/人工结论区分；
- 无法跳转到具体 spoken、音色或 ScriptUnit；
- 批量通过包含阻断问题。

可复用检测算法需包装为版本化检查器；缺少输入和阈值版本的旧结果只能作为历史备注。

## 10. 测试要求

- 漏读、多读、重复、数字和术语错误；
- ASR 同音差异和标点差异；
- 静音、削波、截断、损坏、响度和时长异常；
- 自动重试上限；
- 人工覆盖机器决定；
- 新音频不覆盖旧 QA；
- 阈值升级的重评策略；
- 拒绝已批准片段使章节和导出过期。

## 11. 验收标准

- 每个正式 AudioClip 有机器检查和最终审核状态；
- 每个问题可定位到时间、文本或音频证据；
- 自动重试有上限并保留每次失败；
- 人工可以只处理一个片段；
- 样章产生误报、漏报和人工耗时统计；
- 未批准片段不能进入当前正式章节合成。

## 12. 已确认策略与执行输入

项目负责人于 2026-08-08 冻结下列策略。七个 Gate 均为 `open`；Provider 开关、阈值和 live 证据未齐时不得宣称自动通过或真实能力可用。

| Gate | 状态 | 已选策略 | 仍缺输入或禁止项 |
|---|---|---|---|
| M5-D01 | `open` | ASR、VAD、diarization 按能力独立选择具有正式 API、明确授权和数据策略的 Provider，不因 TTS 同厂而默认采用 | 各能力启用开关和 Provider/dialect/model；accepted ADR、runtime profile、凭据边界、授权夹具/hash、独立 smoke 命令、判定、环境和负责人 |
| M5-D02 | `open` | 非模型音频检测使用外部音频处理 API | API/精确版本/许可/预算/边界、accepted ADR、runtime profile、授权夹具与 live smoke 证据；不得自行切换成本地处理器 |
| M5-D03 | `open` | 使用版本化保守规范化和字符 diff；标点与可能同音只分层提示，不自动判正确 | 规范化、空白/标点、分词、同音、专名/数字/单位和不确定项的精确表达及版本化夹具 |
| M5-D04 | `open` | 使用版本化 policy；确定性损坏阻断，语义/同音项进入 review，阈值由基准决定 | policy version、阈值 profile、重试上限、永久失败/阻断类别、人工批量边界和基准证据 |
| M5-D05 | `open` | 按发布目标选择版本化音频指标 profile；目标未选前不写生产数值 | 发布目标、响度、true peak、静音/削波/截断阈值、测量实现/version 和样章校准证据 |
| M5-D06 | `open` | 说话人 embedding 相似度为可选、非阻断提示；无合法参考资产时关闭 | 启用时的 Provider/算法版本与许可、runtime profile、授权参考资产/hash、live smoke 命令、判定、环境和负责人；不得用于自动绑定或拒绝 |
| M5-D07 | `open` | 可再分发固定回归夹具入库，私有合法样章只保存 hash 和人工评分结果 | 回归集定义/来源/许可、评分表、误报/漏报统计、冻结负责人，以及任务产出的具体 fixture/expected/hash |
