# 阶段 04：角色注册表与状态

状态：`planned`
实现审计：`unverified`
前置阶段：[01 小说导入与文件预处理](./01.小说导入与文件预处理.md)、[03 小说剧本化](./03.小说剧本化.md)

## 1. 目标

建立全项目唯一的 Character Registry，把跨章节名称、称谓、别名和说话人候选归并到稳定角色 ID，并区分角色长期阶段与 ScriptUnit 瞬时状态。

## 2. 范围

- Character、CharacterAlias、CharacterStage；
- 人物提及、别名候选、合并、拆分和人工锁定；
- 角色重要度和默认档案；
- 年龄、身份、长期身体状态和剧情阶段的有效范围；
- ScriptUnit 说话人解析反馈；
- 人工审核、版本和下游过期。

## 3. 非目标

- 不在本阶段生成音色或音频；
- 不把自动说话人聚类标签直接认定为真实角色；
- 角色关系图谱不属于当前正式范围；只有逐项批准并先更新主计划后才可另行规划；
- `docs/ideas/character-voice-and-story-adaptation.md` 中的主角显式指定、完整人物时间线、原生音频时间轴标记等仍是想法，不自动纳入本阶段。

## 4. 核心模型

```ts
interface Character {
  characterId: string;
  canonicalName: string;
  importance: "main" | "supporting" | "minor" | "unknown";
  genderExpression?: string;
  aliases: CharacterAlias[];
  stages: CharacterStage[];
  defaultVoiceProfileId?: string;
  reviewStatus: "pending" | "approved" | "rejected";
}

interface CharacterAlias {
  aliasId: string;
  text: string;
  characterId: string;
  effectiveRange?: StoryRange;
  evidence: EvidenceRef[];
  confidence: number;
  lockedByUser: boolean;
}

interface CharacterStage {
  stageId: string;
  characterId: string;
  effectiveRange: StoryRange;
  ageStage?: string;
  identityStage?: string;
  persistentPhysicalState?: string;
  storyArc?: string;
}
```

`CharacterStage` 表达一段剧情范围内相对稳定的角色阶段；愤怒、恐惧、短时受伤、耳语等当前表现仍保存在 ScriptUnit。

## 5. 角色归并

候选来源包括：

- corrected 文本中的实体提及；
- ScriptUnit 的 speaker mention、称谓和动作证据；
- Scene 人物候选；
- 人工添加和锁定；
- 已确认的项目知识库。

自动归并只能产生候选，至少考虑同章/同 Scene 上下文、称谓、同时出场冲突、首次出现、有效范围和人工锁定。以下操作必须人工确认：

- 合并两个已有稳定角色；
- 拆分已有角色；
- 把常见称谓设为全书别名；
- 修改已经被大量 ScriptUnit 引用的角色 ID；
- 设置或改变长期阶段边界。

## 6. 与剧本阶段的迭代

```text
ScriptUnit speaker mention
→ 角色候选和别名归并
→ Character Registry revision
→ 只重新解析受影响 ScriptUnit
→ 冲突返回角色审核队列
```

不得每章建立独立角色表。跨章节出现的同一人物必须复用稳定 ID；同名但不同人物必须允许拆分并保存证据。

## 7. 页面和审核

角色管理页必须支持：

- 角色列表、别名、出场范围、重要度和审核状态；
- 合并、拆分、重命名、添加别名和锁定；
- 查看每个别名和归并结论的原文证据；
- 查看角色在各章、Scene 和 ScriptUnit 中的引用；
- 编辑 CharacterStage 及其生效范围；
- 在提交前预览受影响的剧本、音色、音频和导出；
- 发现同名冲突、同时出场冲突和无效阶段重叠。

## 8. 版本和过期影响

- 新增未使用别名不使现有产物过期；
- 别名改绑只重新解析命中该别名的 ScriptUnit；
- 角色合并/拆分使受影响 ScriptUnit 的说话人解析、Voice Casting、音频及消费者过期；
- CharacterStage 边界变化只影响该角色且范围相交的单元；
- 仅修改人物备注或头像不应使音频过期，除非导出显式依赖这些字段；
- 角色 ID 不可因显示名称变化而改变。

## 9. 早期实现迁移

重点检查：

- 是否每章生成独立角色 ID；
- 是否把姓名字符串当作主键；
- 是否把别名全部做成全书无条件映射；
- 是否自动合并同名角色；
- 是否没有合并/拆分历史；
- 是否把情绪、临时受伤和年龄阶段混在同一状态；
- 是否把匿名说话人标签当作真实人物。

可保留的名称提取和相似度逻辑只作为候选生成器；无法表达证据、范围和人工锁定的实体模型需要 `migrate` 或 `replace`。

## 10. 测试要求

- 同一角色跨章多称谓归并；
- 同名不同人物拆分；
- 通用称谓不被错误全书合并；
- 合并、拆分和撤销均保留历史；
- Stage 范围不重叠或按明确优先级解析；
- 别名改绑只影响命中单元；
- 人工锁定不会被模型重跑覆盖；
- 角色显示名称变化不改变 ID。

## 11. 验收标准

- 项目使用唯一 Character Registry；
- 主角和长期角色跨章节保持稳定 ID；
- 每个别名映射可查看证据、范围和审核人；
- ScriptUnit 可以解析到角色或明确保持 `unknown`；
- 长期阶段和瞬时状态被清晰分离；
- 角色变化只传播到实际引用范围。
