# 阶段 05：声音系统与音色分配

状态：`planned`
实现审计：`unverified`
前置阶段：[04 角色注册表与状态](./04.角色注册表与状态.md)
架构约束：[ADR 0001：模型能力统一通过 Provider API 接入](../../docs/adr/0001-model-capabilities-via-provider-apis.md)

## 1. 目标

建立与具体 TTS 厂商解耦的 VoiceProfile、VoicePool 和 Voice Casting，使核心角色跨章节保持可追踪的一致配置，并让同一 Scene 的普通角色具有可审核的区分度。

## 2. 范围

- 核心角色 VoiceProfile；
- 普通角色 VoicePool；
- 角色、CharacterStage 与音色版本绑定；
- Scene 内声音冲突检测和分配；
- Provider、模型/服务、Voice ID、参考音频、Provider 侧 Speaker Embedding 引用、Seed 和参数元数据；
- 音色试听、版本、激活、回退和过期传播；
- 音色资产来源、授权状态和质量等级。

## 3. 非目标

- 不在本阶段执行批量 TTS；
- 不承诺固定 Seed 可以跨模型、版本和硬件得到完全相同音频；
- 不把机器相似度直接视为听感验收；
- 不自动使用未完成来源和授权确认的声音资产；
- 原生媒体时间轴标记和完整微调工作台仍以 `docs/ideas/` 状态为准，除非另行批准。

## 4. 核心模型

```ts
interface VoiceProfile {
  voiceProfileId: string;
  lineageId: string;
  revisionId: string;
  displayName: string;
  kind: "fixed" | "cloned" | "designed" | "pooled";
  providerProfileId: string;
  apiDialect: string;
  modelId: string;
  modelVersion?: string;
  providerVoiceId: string;
  providerVoiceVersion?: string;
  referenceAssetIds: string[];
  speakerEmbeddingRef?: string;
  seedPolicy?: object;
  defaultParameters: object;
  rightsStatus: "unverified" | "verified" | "restricted" | "rejected";
  qualityStatus: "pending" | "approved" | "rejected";
}

interface VoiceAssignment {
  assignmentId: string;
  characterId: string;
  characterStageId?: string;
  sceneId?: string;
  voiceProfileRevisionId: string;
  source: "manual" | "rule" | "model";
  lockedByUser: boolean;
}
```

显示名称、角色名称和 VoiceProfile ID 必须分离。Profile revision 不可变；调参、更换 Provider 侧音色资产或 Provider 侧定制结果产生新 revision。

## 5. 核心角色与声音池

核心角色使用显式 VoiceProfile 和锁定版本。普通角色可以从 VoicePool 选择，池中音色按年龄表达、音高、粗糙度、明亮度、语速和风格等可审核标签组织。

同一 Scene 的分配至少满足：

- 不重复使用同一 VoiceProfile revision；
- 避免与当前 Scene 已使用音色明显冲突；
- 核心角色音色不自动分配给普通角色；
- 有稳定 Character ID 的再次出场角色优先复用历史分配；
- 所有自动选择可被人工锁定或替换。

相似度指标只产生提示，最终区分度通过样章试听和人工评价确认。

## 6. 角色阶段与瞬时表现

VoiceProfile 提供角色身份基础；CharacterStage 可以选择不同 Profile revision 或覆盖部分默认参数；ScriptUnit 的瞬时情绪、身体状态和表达方式在运行时生成最终请求。

解析优先级：

```text
ScriptUnit 人工锁定
> CharacterStage 显式绑定
> Character 默认 VoiceProfile
> Voice Casting 候选
> 未分配并阻断 TTS
```

## 7. 音色资产

参考音频至少记录：

- 原始资产 ID、来源、权利人和许可范围；
- 是否允许克隆、微调、团队共享和发布；
- 时间范围、转写和角色候选；
- 背景音乐、重叠人声、混响、截断和噪声标记；
- 清洗链、衍生资产和质量等级。

授权或质量状态未通过时，资产不得被正式 VoiceProfile 引用。

## 8. TTS Provider API 边界

本阶段只定义 TTS Provider adapter 输入所需能力，不固定厂商、API dialect 或模型。VoxWeaver 不运行、下载或分发 TTS 模型。候选 Provider API 至少评估：

- 音色列表、固定音色 ID 和版本信息；
- 参考音频上传、临时引用和 Provider 侧资产引用；
- 发音提示、情绪、语速、音调和输出格式；
- 同步、流式或异步任务模式；
- 取消、限流、幂等、费用、数据保留和删除策略；
- 音色克隆或自定义音色 API 的授权证据和发布限制。

正式采用前必须通过 ADR 记录 Provider、API dialect/版本、认证、模型与音色标识、数据策略、能力映射、基准和退出方案。

## 9. 页面和审核

- VoiceProfile 列表、版本、授权和质量状态；
- 真实项目文本试听和多配置对比；
- Character/Stage 绑定和 Scene 分配；
- 同场景冲突提示；
- 激活新 revision 前显示受影响 ScriptUnit、音频、QA、章节和导出数量；
- 旧音色和旧生成结果继续可试听；
- 人工评价至少覆盖身份一致性、区分度、年龄/状态匹配、发音和长句稳定性。

## 10. 版本和过期影响

- 创建未激活的 Profile revision 不影响现有产物；
- 激活新 revision 只使引用旧活动版本的片段音频及消费者过期；
- 修改显示名称或备注不使音频过期；
- CharacterStage 绑定变化只影响该角色且范围相交的 ScriptUnit；
- VoicePool 标签变化只有在重新分配并激活后才传播；
- 旧音频、试听评价和审核结论不得删除。

## 11. 早期实现迁移

检查旧功能是否：

- 把模型私有字段写入 Character 或 ScriptUnit；
- 直接用角色名查找音色；
- 覆盖旧 Profile 参数；
- 无授权和来源状态；
- 同 Scene 只做随机分配；
- 参数修改后整书全部重生成；
- 把试听结果和正式活动版本混在一起。

模型调用封装可以 `adapt` 为阶段 07 适配器；无版本、来源或授权边界的音色记录必须 `migrate`。

## 12. 测试要求

- Character/Stage 解析优先级；
- Profile revision 不可变；
- 同 Scene 冲突检测；
- 核心角色音色不被池自动占用；
- 未授权资产阻断正式配置；
- 激活新版本只使命中片段过期；
- 旧版本可以比较和回退；
- 人工锁定不会被自动重新分配覆盖。

## 13. 验收标准

- 核心角色跨章节引用稳定 VoiceProfile revision；
- 普通角色分配可解释、可修改、可锁定；
- 同一 Scene 的音色冲突可检测并人工确认；
- 每个 Profile 可追踪模型、参数、参考资产和授权；
- 音色变化只影响实际引用范围；
- 更换后端不改变 Character 和 ScriptUnit 契约。
