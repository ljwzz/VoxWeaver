# 阶段 00：项目基线与工程工作区

状态：`in_progress`
实现审计：M0 后端基础设施 `verified`；切片 `00-01`～`00-06` 已验证；Electron 项目页、最近项目入口及 Main/Preload/Renderer/Core 跨进程基础传输与接线未完成
对应主计划：M0 项目基础设施、工程管理通用部分

## 1. 目标

在任何业务阶段实现前，建立唯一项目上下文、可迁移工作区、版本化产物、依赖图、任务恢复和增量过期机制。后续阶段只通过本阶段提供的端口操作项目状态和文件。

## 2. 范围

- 项目选择、新建、打开、切换和只读打开；
- 项目目录、manifest、状态库、锁、备份和迁移；
- 产物、revision、依赖边、任务和审核的公共模型；
- `current/stale/superseded/missing` 有效性；
- 前序修改的影响预览和最小过期传播；
- 日志、错误码、恢复、授权登记和数据边界；
- 跨模块 JSON Schema 与统一时间、哈希规范。

## 3. 非目标

- 不在本阶段实现小说格式解析、文本校对、TTS 或音频算法；
- 不建设独立网页端；Renderer 只作为 Electron 桌面应用的一部分交付；
- 数据库驱动由 ADR 0002 固定为 `node:sqlite`，项目 Task workflow 由 M0 实现固定；本阶段不替 ARCH-D02 选择桌面打包工具；
- 不实现云端多人协作和分布式调度；
- 不自动升级 `docs/ideas/` 中的产品能力。

## 5. 单项目工作区

每个用户项目对应一个独立目录：

```text
<workspace-root>/projects/<safe-slug>--<project-id>/
├── project.json
├── state/
│   ├── project.sqlite             # 由 ADR 0002 固定为 Node.js 内置 SQLite
│   ├── backups/
│   └── locks/
├── inputs/
│   ├── novels/<source-asset-id>/
│   ├── voice-sources/
│   └── artwork/
├── artifacts/
│   ├── imported/<revision-id>/
│   ├── canonical/<revision-id>/
│   ├── normalized/<revision-id>/
│   ├── corrected/<revision-id>/
│   ├── structure/<revision-id>/
│   ├── knowledge/<revision-id>/
│   ├── scripts/<revision-id>/
│   ├── spoken/<revision-id>/
│   ├── voice-profiles/<revision-id>/
│   ├── renders/<render-set-id>/
│   ├── qa/<revision-id>/
│   └── assemblies/<revision-id>/
├── exports/<export-id>/
├── cache/
├── logs/
└── tmp/
```

目录只承载内容，不充当流程状态。`inputs/` 和正式 revision 不可变；编辑必须创建新 revision。`cache/`、`tmp/` 可重建，不能作为唯一真值。

仓库根目录的 `data/` 不得保存正式用户项目；它只用于开发夹具或迁移前兼容。

## 6. 项目页面

```text
启动
  ├── 可恢复的有效项目 → 按用户设置恢复或询问
  └── 无有效项目       → 项目选择页

项目选择页
  ├── 新建项目
  ├── 打开已有项目
  └── 最近项目
```

新建项目必须：

1. 校验用户选择的父目录；
2. 生成不可变 `project_id` 和安全目录名；
3. 在同一父目录建立临时目录；
4. 写入 manifest、状态库和目录骨架；
5. 验证可以重新打开；
6. 切换为正式目录并登记最近项目；
7. 失败时只清理本次新建的临时目录。

目标目录已存在时不得合并或覆盖。URL 中的 `project_id` 不得直接转换为磁盘路径。路径解析必须规范化并确认仍位于项目根目录内；路径遍历风险说明：

https://owasp.org/www-community/attacks/Path_Traversal

## 7. 公共实体

最少定义：

```text
Project
SourceAsset
Artifact
ArtifactRevision
ArtifactDependency
StageRun
Task
ReviewDecision
StaleCause
ExportSnapshot
```

正式产物记录至少包含：

```ts
interface ArtifactRecord {
  artifactId: string;
  artifactType: string;
  lineageId: string;
  revisionId: string;
  scope: ArtifactScope;
  contentHash: string;
  inputFingerprint: string;
  processorId: string;
  processorVersion: string;
  parametersHash: string;
  executionStatus: string;
  validityStatus: string;
  reviewStatus: string;
  createdAt: string;
  createdBy: string;
}
```

内容哈希统一采用 SHA-256。哈希用于检测内容变化，不替代 ID、来源、授权和审核信息。技术依据：

https://csrc.nist.gov/pubs/fips/180-4/upd1/final

时间字段使用带时区的 RFC 3339，持久化默认 UTC：

https://www.rfc-editor.org/info/rfc3339/

## 8. 三类状态

不得使用单一状态同时表达执行、有效性和审核：

```text
execution_status: pending | running | succeeded | failed | canceled
validity_status:  current | stale | superseded | missing
review_status:    not_required | pending | approved | rejected
```

`succeeded + stale + approved` 是合法组合：产物曾成功并通过审核，但其当前依赖已改变。`superseded` 不表示应删除；`missing` 表示记录存在而物理文件缺失。

## 9. 依赖和输入指纹

每个衍生产物必须显式记录直接依赖及最小稳定 selector：

```ts
interface ArtifactDependency {
  consumerArtifactId: string;
  producerArtifactId: string;
  dependencyType: "content" | "structure" | "voice" | "pronunciation" | "config";
  selector?: {
    chapterIds?: string[];
    blockIds?: string[];
    scriptUnitIds?: string[];
    voiceProfileIds?: string[];
    dictionaryEntryIds?: string[];
  };
}
```

`input_fingerprint` 由直接依赖的 ID、内容哈希、selector、处理参数、兼容性版本、模型、词典、音色和规则版本的规范化表示计算。只有历史产物的输入指纹与当前输入完全一致时才能复用为 `current`。

产物来源、活动和派生关系参考 W3C PROV 的 entity、activity 和 derivation：

https://www.w3.org/TR/prov-dm/Overview.html

## 10. 增量过期传播

确认前序新版本时必须：

1. 保存新版本；
2. 计算稳定单元的真实变更；
3. 遍历依赖消费者；
4. 向用户显示预计影响；
5. 在同一事务中切换活动版本并登记全部过期原因；
6. 保留旧文件和审核记录；
7. 由用户选择立即重处理、稍后处理或保留比较；
8. 新结果成功后重新计算有效性。

| 变更 | 过期范围 | 不受影响 |
|---|---|---|
| 章节内容变化 | 相交结构、剧本、spoken、音频、QA、章节和导出 | 其他可稳定对齐单元 |
| 说话人、情绪、声音状态变化 | 对应音频、QA、章节和导出 | 原文、校正文、其他单元 |
| 发音词条变化 | 实际命中片段及其音频消费者 | 未命中片段 |
| 音色版本激活 | 引用该版本的音频及其消费者 | 文本和其他音色片段 |
| 章节顺序变化 | 全书装配、目录和最终导出 | 章节内容和章节音频 |
| 仅审核备注变化 | 审核视图 | 音频和导出 |

一个产物可以同时有多个 `StaleCause`。解决一个原因不得清除其他原因。`stale` 产物可以查看、试听和比较，但正式导出不得静默包含它；任何豁免都必须生成独立快照并记录原因。

## 11. 任务、事务和恢复

任务唯一键至少包括：

```text
project_id + processor_id + input_fingerprint + output_scope
```

任务先写入 `tmp/`，校验完成后提交到正式 revision。正式文件可读后才能把状态标为成功。相同任务重复投递必须复用运行中或已成功结果。

同一项目同一时刻只有一个逻辑写入者。状态库使用 ADR 0002 已确认的 SQLite；所有“正式文件提交、依赖更新、活动版本切换、过期登记”必须具有明确事务和故障恢复边界。SQLite 的事务行为以官方文档为准：

https://www.sqlite.org/lang_transaction.html

## 12. 数据契约和迁移

- manifest、跨进程 DTO、revision 和工程包清单使用 JSON Schema Draft 2020-12；
- 项目 manifest、目录布局和状态库 schema 分别版本化；
- 破坏性变更必须有迁移、备份和失败恢复；
- 不支持降级时必须阻止旧应用写入；
- 未知字段兼容读取时应该保留，未知枚举不得静默替换；
- 状态库是索引和工作流真值，文件是内容真值；不一致时进入恢复流程。

规范：

https://json-schema.org/specification

## 13. 早期实现迁移

取得早期代码后，按以下顺序审计：

1. 列出实际项目目录和数据库结构；
2. 映射旧实体到公共实体；
3. 检查是否覆盖源文件或移动阶段文件；
4. 检查任务是否可幂等重试；
5. 检查状态是否能表达部分过期；
6. 对每个模块标注 `retain/adapt/migrate/replace/retire`；
7. 先编写迁移夹具，再允许旧项目打开。

## 14. 测试要求

- 新建、失败清理、同名冲突和重新打开；
- 只读打开、写锁冲突和失效锁接管；
- 路径越界和符号链接边界；
- revision 不可变和 schema 校验；
- 多原因过期的添加、部分解决和完全解决；
- 内容恢复一致后的历史产物复用；
- 任务中断、重复投递和应用重启恢复；
- 状态库和目录布局迁移；
- 项目切换后旧请求不得写入新项目。

## 15. 验收标准

- 可以创建、关闭并重新打开空项目；
- 每个项目具有独立目录、ID、manifest 和状态库；
- 任一正式产物可追溯到输入、处理器、参数和操作者；
- 前序修改只使实际依赖的后续产物过期；
- 旧产物不会被自动删除；
- 中断后可以识别可继续、可重试、孤立临时文件和丢失文件；
- 所有阶段可以复用统一工作区和 workflow 端口。

## 17. 实现切片

### 00-01：空项目生命周期

本切片不包含：

### 00-02：项目会话、单写锁与只读打开

状态：`verified`

已实现：

- 每次创建、打开或切换生成独立 `projectSessionId`，项目上下文明确区分 `read-write` 与 `read-only`；
- 创建项目和默认打开使用独占写锁；第二写会话返回稳定冲突错误，只读会话不创建锁且可以与写会话并存；
- 写锁记录版本、项目、会话、进程、主机和获取时间，并通过 JSON Schema 与运行时解析器共同校验；
- 同一 workspace 对同一项目会话的并发关闭共享一次锁释放；释放完成前同实例不会重新获取该项目写锁；
- 关闭只释放当前 workspace 实例实际持有且磁盘所有权一致的锁，不删除其他会话、非法文件或符号链接；
- 写锁先在同目录临时文件完整写入并同步，再以不覆盖已有目标的 hard-link 发布；进程在发布前中断不会留下空或半写的正式锁；
- 项目正式目录预留后若创建失败，不递归删除可能已被其他进程写入的目录，而是保留为隐藏恢复目录；
- Application Core 可以按项目 ID、会话 ID 和读写要求校验活动上下文；关闭或切换后的旧会话会被拒绝；
- 项目切换在关闭阶段失败时保留旧上下文；旧项目已关闭但新项目打开失败时保持无活动项目，允许用户重新选择；
- 通过 contract、application、workspace 和 app-core 测试验证写锁竞争、只读并存、所有权释放、失败数据保全、会话隔离和切换失败边界。

Node.js 提供 `fsPromises.link()` 创建 hard link；POSIX `link()` 语义要求目标已存在时失败而不覆盖。本切片以此发布已完整同步的锁文件：

https://nodejs.org/api/fs.html#fspromiseslinkexistingpath-newpath

https://pubs.opengroup.org/onlinepubs/9699919799/functions/link.html

当前只在本地文件系统验证该协议；网络文件系统、外部进程在路径检查期间主动替换目录或锁路径等对抗性场景仍为 `unverified`。

本切片不包含：

- SQLite 状态库、迁移、备份和最近项目；
- Electron Main、Preload、Renderer 和跨进程消息信封；
- Artifact、Dependency、Task、Review 和过期传播；
- 失效锁判定与接管、残留临时锁清理和完整崩溃恢复；
- 网络文件系统锁，以及对抗性目录替换或锁路径替换。

### 00-03：SQLite 状态库、备份与迁移

状态：`verified`

已实现：

- 新项目创建 layout `2` 和 state schema `1`，每个项目具有独立 `state/project.sqlite`；
- 使用严格表、外键、WAL、`synchronous=FULL`、5 秒 busy timeout 和 `BEGIN IMMEDIATE` 事务；
- 分离不可变 revision/dependency/review 表与可变执行、有效性、审核状态；
- 打开时执行 schema 版本、项目 ID 和 `quick_check` 校验；过新、未知或不匹配的状态库阻止打开；
- 只读会话不执行迁移；layout `1` 和已识别 state schema `0` 由写会话在备份后迁移；
- SQLite 选型、运行时基线、事务和本机文件系统限制由 [ADR 0002](../adr/0002-project-state-with-node-sqlite.md) 固化。

### 00-04：核心记录、Artifact revision 与依赖过期

状态：`verified`

已实现：

- 定义 Project、SourceAsset、Artifact、ArtifactRevision、ArtifactDependency、StageRun、Task、ReviewDecision、StaleCause 和 ExportSnapshot 类型及运行时契约；
- revision 内容在 `tmp/` 校验 SHA-256 后移动到正式目录并同步，`revision.json` 通过版本化 JSON Schema 校验；
- 输入指纹对对象键、依赖顺序和 selector ID 顺序规范化，只有精确指纹、未丢失且未拒绝的历史 revision 可复用；

- 一个 revision 可以保留多个独立 `StaleCause`；部分解决不清除其他原因，全部解决后按活动版本重新计算有效性；
- 重新激活精确历史 revision 会解决对应的反向变更原因，旧文件和审核记录不删除；
- 过期或丢失 revision 的导出必须提供显式豁免原因，并生成独立 ExportSnapshot。

### 00-05：Task、StageRun 与崩溃恢复
