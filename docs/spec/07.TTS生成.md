# 阶段 07：TTS 生成

状态：`planned`
实现审计：`unverified`
前置阶段：[03 小说剧本化](./03.小说剧本化.md)、[05 声音系统与音色分配](./05.声音系统与音色分配.md)、[06 中文发音处理](./06.中文发音处理.md)
架构约束：[ADR 0001：模型能力统一通过 Provider API 接入](../../docs/adr/0001-model-capabilities-via-provider-apis.md)

## 1. 目标

通过统一 TTS Provider API 端口按 ScriptUnit 生成可复现、可缓存、可重试的独立音频片段，不让业务状态依赖具体厂商 API 私有字段。VoxWeaver 不运行、下载或分发 TTS 模型。

## 2. 范围

- TTS 请求、响应、能力、错误和健康检查契约；
- Provider adapter；
- ScriptUnit 级生成；
- 输入指纹、缓存、并发、超时、重试和取消；
- 模型、音色、参考音频、参数、Seed 策略和输出哈希记录；
- 片段试听和最小重生成。

## 3. 非目标

- 不整章一次生成；
- 不把后端模型字段写回 ScriptUnit；
- 不把随机 Seed 视为跨环境完全确定性的保证；
- 不在本阶段决定 QA 通过或正式导出；
- 不允许未审核 ScriptUnit、spoken 或 VoiceProfile 进入批量正式生成。

## 4. 统一端口

```ts
interface TtsProviderAdapter {
  readonly adapterId: string;
  readonly adapterVersion: string;

  capabilities(): Promise<TtsCapabilities>;
  validate(request: CanonicalTtsRequest): Promise<ValidationResult>;
  synthesize(request: CanonicalTtsRequest, signal: AbortSignal): Promise<TtsResult>;
}

interface CanonicalTtsRequest {
  projectId: string;
  scriptUnitId: string;
  providerProfileId: string;
  modelId: string;
  spokenRevisionId: string;
  spokenText: string;
  voiceProfileRevisionId: string;
  characterStageId?: string;
  emotion?: object;
  physicalState?: object;
  speechStyle?: object;
  pronunciationHints?: object[];
  seedPolicy?: object;
  outputSpec: AudioOutputSpec;
}
```

适配器必须声明其 API dialect、请求模式、能力和不支持字段。业务层不允许根据 adapter ID 编写厂商专用分支。

## 5. 生成单元和输入指纹

最小正式生成单位为 ScriptUnit。输入指纹至少包含：

```text
spoken 内容和 revision
voice profile revision
角色阶段和瞬时表现
发音提示
provider profile / API dialect / model / service version（若可获取）
生成参数和 seed policy
音频输出规格
```

缓存只在完整输入指纹和输出规格一致时命中。输出记录保存文件哈希、时长、采样率、声道、模型响应元数据和任务日志。

## 6. 任务行为

- 相同任务重复投递必须幂等；
- 临时输出先写入项目 `tmp/`，校验后提交正式 render set；
- 超时、取消、资源不足和后端拒绝必须使用结构化错误码；
- 自动重试只适用于明确可重试错误并有次数上限；
- 参数或文本错误不得盲目重试；
- Provider 请求中断后必须根据请求 ID、幂等能力和异步任务状态判定恢复，不盲目重提可能计费的请求；
- 用户可以选择单句、角色、Scene、章节或过期集合批量生成。

## 7. Provider API 准入

候选 Provider 只用于基准比较，不在计划中固定厂商或模型：

- 必须提供可由 TypeScript adapter 调用的 HTTP/HTTPS API；
- 必须声明同步、流式或异步任务模式；
- 必须明确音色、参考音频、发音提示和输出格式能力；
- 必须可记录 Provider 请求 ID、模型/服务标识、使用量或可用的计费信息；
- 必须提供数据保留、授权、限流、错误和退出说明。

每个采用 Provider 必须在 ADR 中固定 Provider、API dialect/版本、认证方式、模型与音色标识、数据策略、能力映射、基准和替换方案。

## 8. 页面和任务监控

- 按项目、章节、角色、后端和状态查看任务；
- 单句生成、重试、取消和多版本试听；
- 显示输入指纹、模型、音色、参数和缓存命中；
- 不覆盖旧音频；
- 标记当前、过期、失败和待 QA；
- 后端或配置升级前执行固定样本对比并预览影响。

## 9. 版本和过期影响

- 新后端或配置版本未激活时不影响现有音频；
- spoken、VoiceProfile、相关状态或输出规格变化只使命中 ScriptUnit 的音频及消费者过期；
- adapter 代码升级只有在兼容性版本变化并激活后才传播；
- 缓存清理不能删除正式 render 产物；
- 重新生成成功后旧版本继续可比较，活动指针切换必须事务化。

## 10. 早期实现迁移

检查旧实现是否：

- 整章生成或按文件覆盖；
- 缓存键缺少模型、音色、发音或参数；
- Character/ScriptUnit 存储后端私有字段；
- 失败重试无上限；
- 任务不可取消或重复投递产生覆盖；
- 旧音频无法追溯到输入；
- 把试听输出当作正式产物。

模型客户端可 `adapt` 为适配器；无法重建输入指纹或来源的旧音频只能作为外部历史资产导入。

## 11. 测试要求

- 适配器契约和能力降级；
- 完整输入指纹与缓存命中；
- 不同模型/音色/发音/参数不错误共用缓存；
- 超时、取消、可重试和不可重试错误；
- 重复投递幂等；
- 中断恢复和临时文件清理；
- 单句修改不重建无关片段；
- adapter 升级不覆盖旧产物。

## 12. 验收标准

- 每个 ScriptUnit 独立生成和重试；
- 更换后端不改变领域契约；
- 每个音频可追踪到全部输入和处理版本；
- 相同输入指纹可以复用成功结果；
- 失败不会破坏其他片段或旧版本；
- 中断后可以从未完成范围继续；
- 未通过授权和审核的输入不能进入正式批量任务。
