# 阶段 01：小说导入与文件预处理

## 目标

进入项目后，把已经保存的小说源文件副本整理为结构清晰、来源可追溯、便于后续处理的项目文本。

## 与新建项目的边界

- 本阶段只在阶段 00 已成功创建项目并保存项目源文件副本后开始。
- 本阶段读取项目内的源文件副本，不再依赖用户最初选择的项目外部文件。
- 格式识别、编码确认、文本提取和转换文件保存只在正式项目工作台执行，不得提前并入新建项目流程。
- 本阶段的识别或转换失败只阻止进入后续文本处理，不得使阶段 00 已创建成功的项目或源文件副本失效。

## 工作步骤

1. 在项目内加载已经保存的源文件副本。
2. 识别并确认文件格式、编码和基础书目信息。
3. 提取文本并统一排版、空白和基础字符表达。
4. 识别卷、章节、场景和原文位置。
5. 预览识别结果并调整章节、标题和边界。
6. 生成导入报告和后续步骤可用的小说结构。

## 阶段结果

形成已确认的小说结构、章节顺序、场景边界和来源定位。

## 当前工程契约

### SourceAsset 与编码

- 仅读取 manifest 绑定的项目内 TXT SourceAsset；每次读取重新校验普通文件、路径 containment、byte length 和 SHA-256，不再次选择外部文件。
- UTF-8/UTF-16LE/UTF-16BE BOM 自动确认；无 BOM 时只自动确认严格 UTF-8。
- 其他输入使用 `chardet` 统计候选作为默认建议，不将建议视为确定结论；无可映射候选时不预选。`GB18030` 建议不得伪装成 GBK 或 GB2312。
- 编码可人工选择 UTF-8、GB2312、GBK、GB18030、Big5、UTF-16LE 或 UTF-16BE。手动选择绑定当前 SourceAsset hash 并对全文严格解码；UTF-32、空文本、NUL 和无效字节序列直接拒绝。

### 编码预览与确认

- 文本提取页按当前编码从 SourceAsset 原始字节渐进读取只读正文，不一次经 IPC 返回全文，不提前执行章节分析或规范化。
- 预览请求绑定 source hash 和当前编码，使用原始文件 byte cursor；单次最多 1,000 行且最多 256 KiB，返回游标必须落在字符边界并正确处理 CRLF、LF、CR 和 BOM。
- 首批读取两个可见视口；缓冲区剩余不超过半个视口时自动预取。快速滚动按本次滚动行差增大下一批，每批为二到八个视口。
- 仅当当前 source hash 和编码的首批预览成功后，才允许“确定文本解析正确”。编码切换必须清空旧预览、重置游标并丢弃迟到响应。

### 任务与产物

- 导入指纹由源 hash、确认编码和处理器版本生成；同一有效输入复用现有 pending/running/succeeded 任务。
- 任务状态为 `pending/running/succeeded/failed/canceled`，提供进度事件、取消、重试和 Core 中断后的 retryable 恢复。
- 失败不得修改 SourceAsset 或最后一个有效 revision；成功后才原子发布 UTF-8 文本、复核快照和 artifact/任务记录。
- 发布的 `text.utf8.txt` 为项目内部版本化产物，使用无 BOM UTF-8；本阶段不生成项目外导出副本。

### 章节复核

- 复核快照包含章节、UTF-8 byte 边界、覆盖报告和 revision history。旧快照缺少新字段时，读取层补齐 `headingKind: 'source'` 和 `lengthAnomalyAccepted: false`。历史 revision 的规范化正文若仍包含 CRLF 或 CR，编辑器只在显示层映射为 LF 逻辑行，命令范围与插入点仍按历史正文的 UTF-8 byte offset 表示。
- 原文标题章使用 `headingKind: 'source'` 并必须保留非空标题范围。无标题章使用 `headingKind: 'missing'`，不保存标题范围，持久化标题固定为“未命名章节”，界面再按文档顺序显示“未命名章节 N”。正文范围可以为零长度，以表达空章。
- 边界、新增识别、合并、删除、换行和异常确认先累积为同一本地草稿。`update-chapter-structure` 命令绑定当前 baseline：换行插入点按 baseline 正文的 UTF-8 byte offset 表示，最终章节投影和显式未归属范围按插入换行后的 UTF-8 byte offset 表示。
- 章节投影的数组位置决定顺序；已有章必须携带 `existingChapterId`，新章不携带并由 Core 生成永久 ID。删除识别不删除正文，其归属范围必须进入显式未归属范围。至少保留一个有效章节时，显式未归属范围不阻止阶段确认；空章或章节长度异常只提示，不参与门禁。
- Footer 预览与应用必须使用完全相同的命令哈希；一次保存只创建一个 baseline/revision，并将受影响的下游依赖写入指向新 revision 的 stale cause。基线冲突时拒绝提交并保留草稿，不静默重放。
- 命令不含换行插入时复用当前规范化文本；命令含换行插入时发布新的 `text.utf8.txt` 和 `review.json`。两种情况均不修改 SourceAsset。
- 章节正文只通过 UTF-8 byte range 读取；每次最多 256 KiB，范围必须落在 UTF-8 字符边界，且 artifact 路径不得越出项目或包含符号链接。
- 确认后阶段 02 进入“前置已满足但能力尚未实现”的门禁状态。
