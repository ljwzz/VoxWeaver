# 角色音色与小说剧本化想法

状态：想法记录，尚未纳入正式实施计划。

记录日期：2026-07-30。

## 目标与作用

这组想法用于增强 VoxWeaver 对长篇小说中核心人物、人物成长轨迹、声音状态变化和多人场景的表达能力。

核心目标：

- 允许用户明确指定并深度定制主角；
- 让角色声音随情绪、年龄、健康状况和剧情阶段变化；
- 从真实项目文本中选取有代表性的内容调试音色；
- 从合法取得的视频或音频中直接标记候选音色片段；
- 将原生小说转换为带角色层级、状态和声音信息的结构化剧本；
- 在同一场景中减少配角和龙套的音色重复。

## 步骤一：全书分析与人物时间线

### 作用

先建立全书级剧情和人物变化基线，为后续角色状态标注、音色选择和声音微调提供依据。单章局部分析不足以判断人物年龄变化、重大转折或长期情绪状态。

### 功能要求

- 分析小说大纲、卷章结构、主要剧情线和关键冲突。
- 识别主要人物及其关系、出场范围和剧情权重。
- 建立人物时间线，标记可能影响声音表现的事件：
  - 出生、童年、青年、中年、老年；
  - 成长、衰老、死亡和复生；
  - 重伤、疾病、恢复、虚弱和身体异变；
  - 身份变化、重大失败、突破、失去亲友和性格转折；
  - 长期压抑、亢奋、冷漠、疯狂等持续状态。
- 将这些事件记录为候选“声音变化点”，由人工确认是否需要切换角色声音状态。

### 数据要求

每个变化点至少记录：

```json
{
  "character_id": "character_001",
  "event_id": "event_001",
  "event_type": "age_or_life_transition",
  "chapter_id": "ch120",
  "source_range": {
    "start": 1024,
    "end": 1188
  },
  "summary": "人物进入老年阶段",
  "suggested_voice_state": "elderly",
  "confidence": 0.91,
  "review_status": "pending"
}
```

### 约束

- 大纲和人物变化分析只能生成候选结果，不得直接改变角色音色。
- 生老病死等事件必须保留原文依据和章节定位。
- 同一人物可以在一个阶段同时具有年龄、身体、情绪和剧情弧线等多维状态。

## 步骤二：主角指定与角色档案

### 作用

主角是需要最高一致性和最多声音状态的角色，不能只依赖自动识别或普通角色配置。

### 功能要求

- 用户可以从已识别人物中明确指定一个或多个主角。
- 支持取消主角、调整主角优先级以及处理多主角作品。
- 主角档案除 `aliases` 外，还应包含：
  - 人物身份和称谓；
  - 性别表达；
  - 年龄阶段；
  - 身体状态；
  - 性格和长期表达风格；
  - 剧情阶段；
  - 默认声音状态；
  - 可用声音状态列表；
  - 原生参考音频和生成音色配置。
- 主角配置必须支持人工覆盖自动分析结果。

### 建议数据结构

```yaml
id: character_001
name: 主角名
role_level: protagonist
aliases:
  - 别名
priority: 1
default_voice_state: adult_neutral
voice_states:
  - child
  - youth
  - adult_neutral
  - adult_injured
  - adult_angry
  - elderly
```

## 步骤三：角色声音状态建模

### 作用

同一主角不能只绑定一个固定音色。不同情绪和人生阶段需要选择不同参考音源或生成配置，同时保持角色身份可辨识。

### 功能要求

- 每个主角支持多个声音状态。
- 声音状态至少允许组合以下维度：
  - 年龄阶段；
  - 情绪；
  - 身体状况；
  - 剧情阶段；
  - 表达方式，例如耳语、战斗、传音或内心独白。
- 每个声音状态可以绑定不同的：
  - 原生参考音频；
  - Provider 侧自定义音色或微调资产引用；
  - TTS Provider profile 和 API dialect；
  - 生成参数；
  - 语速、音高、能量和停顿策略。
- 支持状态继承。例如 `adult_injured` 可以继承 `adult_neutral` 的角色基础音色，只覆盖虚弱程度和语速。
- 支持人工试听、调整、版本化和回退。

### 状态选择优先级

建议按以下顺序确定片段使用的声音：

1. 人工锁定的片段级声音状态；
2. 剧本明确标注的角色状态；
3. 人物时间线在当前章节生效的状态；
4. 当前场景或情绪推断状态；
5. 角色默认声音状态。

### 约束

- “不同状态”不必然等于完全不同的说话人音色，应优先保持角色身份一致性。
- 自动推断的状态必须记录置信度和依据。
- 修改状态配置时，只使使用该配置的片段进入重新验证队列。

## 步骤四：原生音频与音色来源标记

### 作用

允许用户直接从视频或音频素材中标记候选片段，逐步积累角色在不同情绪和阶段下的音色来源，后续再执行分离、清洗、转写和质量评估。

### 功能要求

- 导入合法取得的视频或音频资产。
- 在播放器时间轴上标记候选区间。
- 每个标记区间可以填写或自动建议：
  - 角色；
  - 声音状态和情绪；
  - 开始时间和结束时间；
  - 台词文本；
  - 来源作品、集数或文件；
  - 背景音乐、音效、重叠人声和混响情况；
  - 适用范围；
  - 授权状态。
- 标记完成后创建“音色来源后期优化任务”，不要求立即完成音频清洗。
- 后期任务支持：
  - 提取无损音频；
  - 人声分离；
  - 通过 Provider API 执行 VAD 切片；
  - 通过 Provider API 执行 ASR 转写；
  - 通过 Provider API 产生匿名说话人候选，再人工确认真实角色；
  - 降噪与响度检查；
  - 质量分级；
  - 关联角色声音状态。

### 建议数据结构

```json
{
  "source_asset_id": "video_001",
  "start_ms": 738400,
  "end_ms": 744200,
  "character_id": "character_001",
  "voice_state": "adult_calm",
  "transcript": "候选台词",
  "quality_flags": ["background_music"],
  "rights_status": "verified",
  "optimization_status": "queued"
}
```

### 约束

- 标记区间只是候选音色来源，未完成质量和授权确认前不得直接用于生产生成。
- 保留源文件、时间区间、处理链和衍生音频之间的关联。
- 原始媒体不得被清洗结果覆盖。

## 步骤五：从真实项目文本提取调试段落

### 作用

音色调试需要使用当前作品真实存在的语言风格、人物称谓、专有名词和情绪表达，通用测试句不能完整暴露实际项目中的发音和表现问题。

### 功能要求

- 从当前项目的原始或校正文本中提取候选测试段落。
- 支持按以下条件筛选：
  - 指定人物；
  - 指定声音状态或情绪；
  - 旁白、对话或内心独白；
  - 专有名词和多音字覆盖；
  - 句长；
  - 平静、激烈、虚弱、悲伤等表达类型。
- 自动推荐能覆盖多类问题的最小测试集。
- 用户可以在音色调试界面直接选择片段、生成、播放和对比多个配置。
- 每次测试记录文本版本、声音状态、音源、模型、参数、输出和人工评价。
- 测试片段保留原章节和原文位置，不能复制后失去来源。

### 建议测试集

- 中性短句：检查角色身份和基础清晰度；
- 中性长句：检查长句稳定性和停顿；
- 情绪句：检查状态表达；
- 专有名词句：检查发音；
- 数字和单位句：检查文本归一化；
- 角色标志性句段：检查角色匹配度；
- 状态变化前后句段：检查声音过渡。

## 步骤六：小说转结构化剧本

### 作用

把原生小说转换为可审核、可生成的剧本，使每个片段明确对应叙述类型、角色层级、人物状态和声音配置。

### 功能要求

- 保留小说原文定位，不直接覆盖原文。
- 剧本片段至少区分：
  - 旁白；
  - 主角；
  - 配角；
  - 龙套；
  - 群体发言；
  - 未知说话人。
- 主角片段必须标记当时的角色状态，用于选择对应声音状态。
- 配角可以具有独立角色档案和声音状态，但默认配置复杂度低于主角。
- 龙套需要标记所在场景、临时身份和声音分配结果。
- 每个片段支持情绪、动作、语速、音量、停顿和表达方式。
- 旁白中的引用、转述、内心活动、传音和梦境需要明确标记，避免被误当作普通对话。

### 建议片段结构

```json
{
  "segment_id": "ch001-000042",
  "type": "dialogue",
  "role_level": "protagonist",
  "speaker_id": "character_001",
  "character_state": {
    "age_stage": "adult",
    "physical": "injured",
    "emotion": "guarded",
    "story_arc": "after_major_defeat"
  },
  "resolved_voice_state": "adult_injured_guarded",
  "text": "原文台词",
  "spoken_text": "朗读文本",
  "scene_id": "scene_001",
  "review_status": "pending"
}
```

### 约束

- 角色层级用于工作流优先级和配置深度，不用于改变原作人物重要性。
- 自动转换后必须保留不确定项，不能通过猜测强制填充说话人或状态。
- 剧本修改必须能反查原文，但不得反向覆盖原始小说。

## 步骤七：场景内龙套音色分配

### 作用

避免同一场景中的多个临时角色使用相同音色，导致听众无法区分说话人。

### 功能要求

- 为龙套建立可复用的通用音色池。
- 音色池按年龄、性别表达、音高范围、音色特征、语速和风格建立标签。
- 分配时考虑当前场景中已使用的音色，优先选择差异明显的配置。
- 同一个有名字或跨场景再次出现的龙套应保持音色一致。
- 纯临时角色可以在不同场景复用音色，但同一场景内不得冲突。
- 分配结果允许人工锁定或替换。

### 建议冲突规则

- 同一场景中不得分配相同 `voice_profile_id`。
- 音色相似度超过设定阈值时给出冲突提示。
- 主角和主要配角使用的核心音色不得自动分配给龙套。
- 群体发言可以使用多音色混合，但必须与独立台词区分。

## 步骤八：调试、审核与持续优化

### 作用

把音色调试、真实文本试听、声音变化点和音源优化连接成可追踪的迭代流程。

### 功能要求

- 从人物时间线进入对应声音变化点的调试任务。
- 从角色声音状态进入真实文本测试集。
- 从测试结果反查原生音源、模型版本和生成参数。
- 支持并排试听同一文本的多个音源或参数版本。
- 支持记录评价维度：
  - 角色身份一致性；
  - 年龄和身体状态匹配；
  - 情绪表达；
  - 发音正确性；
  - 长句稳定性；
  - 与相邻状态的过渡自然度。
- 将未解决问题转为后期优化任务，并关联具体角色、状态、文本和音源。

### 状态建议

```text
IDEA_CAPTURED
→ SOURCE_MARKED
→ SOURCE_CLEANED
→ VOICE_STATE_CONFIGURED
→ TEST_TEXT_SELECTED
→ GENERATED
→ REVIEWED
→ APPROVED
```

## 依赖与约束

- 依赖全书人物知识库、章节定位和实体别名能力。
- 依赖稳定的原文、校正文和朗读文本版本关系。
- 依赖角色、场景、剧情事件和音频资产的统一标识。
- 依赖可插拔 TTS、ASR、音频处理和媒体播放器接口。
- 所有原生视频、音频和声音定制必须先确认授权范围。
- 全书分析和剧本转换可能消耗较多模型资源，应支持分卷处理、缓存和增量更新。

## 待确认问题

- 一部作品是否允许多个同等优先级主角。
- 主角声音状态采用固定枚举、自由标签还是两者结合。
- 年龄变化、身体状态和情绪的组合是否生成独立状态，还是运行时叠加参数。
- “原生音频定制”优先用于零样本参考、微调数据，还是同时支持。
- 音色相似度使用机器指标、人工标签还是组合判断。
- 小说大纲和人物时间线的人工审核粒度。
- 跨卷、回忆、梦境和时间跳跃对人物状态生效范围的处理方式。
- 龙套跨场景再次出现时，如何判断其是否为同一人物。

## 建议的后续落地阶段

如需纳入正式计划，建议拆为以下独立能力：

1. 主角指定、角色层级和角色档案。
2. 真实项目文本测试集与音色试听调试。
3. 视频/音频时间轴标记和音源优化任务。
4. 小说转结构化剧本及角色状态标注。
5. 全书大纲、人物时间线和声音变化点。
6. 多状态主角音色与状态解析器。
7. 场景内龙套音色冲突检测和自动分配。
8. 跨阶段声音一致性评估和持续优化。
