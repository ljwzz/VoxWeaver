# TTS 后立即 ASR 的剧本行内质量反馈

状态：想法记录，尚未纳入正式实施计划。
记录日期：2026-08-08。

## 目标与价值

将用户看到的“语音生成”设计为一个连续步骤：每个剧本行的 TTS 音频生成成功后，系统立即触发 ASR 回听并与该行的 `spoken` 文本比较。

- 转录一致时不显示警告，避免正常剧本行产生额外审核负担；
- 转录不一致时，在对应剧本行原位显示警告，使问题不脱离生成上下文；
- 用户不需要在“07 TTS 生成”和“08 音频 QA”两个页面之间切换；
- 后台仍保留独立 TTS 与 QA 记录，以便重试、版本追踪和后续扩展其他音频检查。

## 所处流程步骤

该想法位于正式计划的阶段 07 与阶段 08 之间，但页面上表现为同一个“生成与校验”步骤：

```text
剧本行（ScriptUnit + spoken revision）
→ TTS 生成 AudioClip revision
→ 音频产物提交成功
→ 自动创建对应 QA 任务
→ ASR 转录
→ 规范化目标文本和转录文本
→ 生成文本差异与 QA 结论
→ 回写当前剧本行状态
```

后台不能把 ASR 同步塞进 TTS 请求。建议采用两个关联任务：TTS 任务成功提交音频产物后触发 QA 任务。页面将两个任务聚合到同一剧本行，因此不暴露为两个用户操作步骤。

以上是产品与架构建议，不是已确认实现方案。

## 页面与交互要求

### 剧本行状态

每个剧本行至少需要区分：

| 行状态 | 页面表现 |
|---|---|
| 待生成 / 生成中 | 显示生成进度，不显示质量警告 |
| 已生成，待 ASR | 显示“校验中”或等价弱状态 |
| ASR 校验中 | 保持当前行可播放，显示校验进度 |
| 转录一致 | 不显示警告；该行保持正常状态 |
| 转录不一致 | 在该剧本行立即显示“转录不一致”警告 |
| TTS 失败 | 显示生成失败，不创建内容不一致警告 |
| ASR 服务失败 | 显示“校验失败/待校验”，不得误报为转录不一致 |

“立即”指单个剧本行的 ASR 结果完成后立即更新该行，不等待整章或整个批次完成。

### 不一致警告

警告必须绑定 `script_unit_id`、当前 `audio_artifact_id` 和 `spoken_revision_id`，并支持展开查看：

- 目标 `spoken` 文本；
- ASR 原始转录文本；
- 规范化后的差异位置；
- ASR、比较规则和阈值版本；
- 重新生成音频、重新执行 ASR、修改 `spoken` 或进入发音处理的操作入口。

警告文案应表达“转录结果与目标文本不一致，需要复核”，不能直接断言“TTS 发音错误”。普通话语音到汉字转录存在同音字和语言模型选择等影响，字符不同不必然等于实际读音错误：

<https://arxiv.org/abs/2108.01129>

## 一致性判定建议

比较目标必须是实际送入 TTS 的 `spoken` revision，不是原始小说文本或未经朗读归一化的剧本文本。

MVP 建议采用可解释的两步判定：

1. 保存 ASR 原始输出，不覆盖；
2. 对目标文本和 ASR 文本执行同一套、版本化的保守规范化，再做精确比较。

保守规范化可以先处理空白、标点和明确等价的格式，但不能静默忽略人名、数字、单位、否定词或其他影响内容的字符。若规范化后完全一致，则不显示警告；否则显示警告并保留插入、删除和替换差异。

NIST 的 ASR 评估将删除、插入和替换作为识别错误的基本分类，并单独规定参考文本规范化；这可作为差异证据结构的依据，但不直接决定本产品阈值：

<https://www.nist.gov/system/files/documents/2021/08/03/OpenASR20_EvalPlan_v1_5.pdf>

中文字符错误率、同音处理、专名加权和允许阈值继续保留为待校准项。不能在没有合法样章回归数据时提前固定生产阈值。

## 功能要求

- 每个成功的正式 AudioClip revision 自动且幂等地创建一次 QA 任务；
- QA 任务只校验触发它的音频和 `spoken` revision，不能读取后来变化的活动版本；
- 单行完成后独立推送或轮询更新，不等待整章；
- 重新生成产生新的 AudioClip revision，并自动触发新的 QA revision；
- 只重新执行 ASR 时复用当前音频，不重复调用 TTS；
- 新 QA 结果不能覆盖旧结果，页面只将当前活动版本聚合到剧本行；
- 批量生成时允许多行并发，但每行状态和警告互不覆盖；
- 不一致默认进入人工复核，不在 MVP 中自动无限重生成；
- ASR 实现通过适配器接入。FunASR 官方项目当前提供 ASR、时间戳、VAD 和标点等候选能力，可用于后续基准比较：
  <https://github.com/modelscope/FunASR>

## 数据与状态要求

建议在现有 `QAResult` 概念上补充或明确以下关联：

```ts
interface InlineTranscriptCheck {
  qaResultId: string;
  scriptUnitId: string;
  audioArtifactId: string;
  spokenRevisionId: string;
  asrAdapterId: string;
  asrModelVersion: string;
  rawTranscript: string;
  normalizedTarget: string;
  normalizedTranscript: string;
  diff: TranscriptDiff[];
  comparisonPolicyVersion: string;
  status: "pending" | "running" | "match" | "mismatch" | "check_failed";
  failureCode?: string;
  createdAt: string;
  completedAt?: string;
}
```

页面行状态应由 TTS task、AudioClip revision 和 QAResult 聚合产生，不能只把一个 `warning` 布尔值写回 ScriptUnit。ScriptUnit 是剧本输入，生成和 QA 是其版本化消费者。

## 依赖和约束

- 依赖稳定的 `script_unit_id`、`spoken_revision_id` 和 AudioClip revision；
- 依赖幂等 Job、任务关联和单行状态更新机制；
- 依赖可替换 ASR 适配器及其模型版本记录；
- 依赖版本化文本规范化和 diff 实现；
- 页面同一步骤不等于合并后台领域职责，阶段 07 仍负责产生音频，阶段 08 仍负责消费音频并形成 QA 结论；
- ASR 结果只是一项机器证据，转录不一致警告不能自动替代听感和发音人工判断；
- 校验失败、任务取消和基础设施错误必须与内容不一致分开；
- `spoken`、音频或比较策略版本变化时，只使对应 QA 结果过期，不修改其他剧本行。

## 待确认问题

- 页面步骤最终命名为“语音生成”“生成与校验”还是其他名称；
- 转录一致后是否完全无标记，还是保留一个可弱化查看的“已校验”状态；
- MVP 是否严格采用规范化后精确一致，还是允许非关键字符差异；
- 同音字差异只显示普通警告，还是增加“可能同音”的辅助分类；
- 人名、术语、数字和单位是否需要更高警告级别；
- 转录不一致是否阻断章节合成，还是必须经人工确认后才决定；
- ASR 超时和失败的自动重试次数、并发和资源限制；
- 警告展开后优先提供哪些修复入口。

## 建议的后续落地阶段

1. **MVP 行内闭环**：TTS 成功自动触发 ASR；保守规范化后精确比较；不一致时显示行内警告；支持重跑 ASR 和单行重生成。
2. **人工复核增强**：差异高亮、试听定位、问题分类、人工接受/拒绝和返回 spoken/发音处理。
3. **校准与分级**：使用合法样章统计误报、漏报和人工耗时，再评估同音辅助、字符错误率、专名加权和阻断阈值。
4. **完整音频 QA**：在同一页面状态模型下接入静音、削波、截断、响度和其他音频检查，不改变“正常行不显示警告、异常行原位提示”的交互原则。
