本规格把 M5 拆成可单独实现、测试和交接的任务卡，不替代上位计划。权威顺序统一遵循 [无人值守执行协议第 2 节](../无人值守执行协议.md#2-权威顺序)；下列只是 M5 相关读取顺序：

1. `项目计划.md` 的产品范围、人工审核和可追溯原则；
2. `docs/spec/90.MVP联调与验收.md` 的 M5 映射；
3. `docs/spec/08.音频QA.md` 的领域要求；

5. 已冻结 schema；

7. 本规格的任务顺序、文件白名单和验证命令。

冲突时停止当前卡片并记录阻塞。执行模型不得修改上位计划、ADR、Decision TODO、冻结夹具或阈值结论。

## 2. 范围与非目标

M5 的完成标志：

- 每个当前正式 AudioClip 可建立独立 QA revision，并引用目标 SpokenUnit revision；
- 外部 ASR Provider 的能力、请求、结果、时间戳、错误和恢复通过通用 port 隔离；
- 文件完整性、时长、静音、削波、截断候选及 M5-D05 选中分支启用的响度/峰值和其他指标以版本化检查器输出证据；
- spoken 与 ASR transcript 的差异、专名/术语/数字/单位加权项可定位且与音频问题分开；
- 机器结论和人工最终结论分别保存；人工可以覆盖机器 pass/warning/fail；
- 自动重试有已批准上限，连续失败进入人工队列，所有 AudioClip 和失败原因保留；
- 问题可以返回 ScriptUnit、spoken/词典、VoiceProfile/Assignment 或 TTS 参数/重生成入口；
- 只有活动 AudioClip 与活动、最终 approved 的 QAResult 组合可交给章节合成；
- QA 算法/阈值版本变化不会原地改写旧结论，重评产生新 revision。

M5 不包含：

- 章节拼接、响度后期处理、时间轴、字幕或发布导出；
- 把 ASR 字符差异、同音转写差异或单一音频指标直接当作最终听感；
- 自动无限重生成、失败时覆盖旧 AudioClip 或修改旧 QAResult；
- 直接修改 ScriptUnit、spoken、词典、VoiceProfile 或 TTS 请求；修复必须回到对应阶段创建新 revision；
- 内置、下载、加载、托管或启动 ASR/VAD/说话人分析模型；
- 把 diarization 匿名标签或声音相似度自动绑定到真实 Character；
- 在合法样章校准前由执行模型预填生产阈值；
- `docs/ideas/` 中未批准的完整声音取证、复杂后期或关系图谱能力。

## 3. 小模型执行协议

每次只执行一个任务 ID，每张卡只交付一个单一结果。

开始前必须：

1. 读取根 `AGENTS.md`、本规格第 2～5 节、当前卡片及其输入；
2. 运行 `git status --short` 并记录既有 staged、modified、untracked 文件；
3. 核对 M4 稳定交付、前置任务和相关 Gate；
4. 只读取卡片涉及的当前接口；找不到符号时才扩大只读搜索；
5. 确认写白名单文件没有并发占用。

执行时必须：

- 只修改“允许写入”文件；共享 index、package manifest 和 lockfile 的卡片串行；
- 先写失败测试或冻结合成夹具，再写最小实现；测试从 `dist` 导入；
- schema、检查器、差异算法、阈值、策略、adapter 和 QA revision 显式版本化；
- 默认测试使用 deterministic Mock ASR 和可再分发合成音频，不发送真实项目音频；
- 未关闭 Gate 时不选择 Provider、音频组件、阈值、相似度或自动重试行为；
- 不执行 git 暂存、提交、重置、清理或全仓自动修复；
- 不把单包测试、Mock、live smoke 或静态文档检查表述成 M5 已完成。

结束前必须运行：

```bash
git diff --check
git status --short
```

交接格式：

```text
任务：M5-XX
结果：complete | blocked | failed | not_applicable
修改文件：逐项列出
验证：命令、退出码和关键断言
Provider：none | mock | live-approved
音频数据：synthetic | approved-project-audio
未验证：逐项列出
既有改动：是否保持不变
阻塞：Gate、TODO、错误文本或缺失输入
```

## 4. 公共不变量

- AudioClip、SpokenUnit、ScriptUnit、VoiceProfile 和 TTS 请求记录均为只读输入；
- QAResult revision 提交后不可变，机器结论、人工最终结论和审核备注是分离字段；
- 每个 QAIssue 必须有类型、严重度、证据、时间/文本定位、检查器版本、阈值策略版本和建议返回阶段；
- ASR transcript 是检查证据，不是 spoken 或 corrected 的替代文本；
- 标点、分词或同音差异不得在未通过批准策略时直接生成发音失败结论；
- diarization/相似度只产生匿名标签、区间和证据，不得直接写 Character ID；
- 任何自动通过、warning、fail、重试上限和批量操作都必须引用已激活策略 revision；
- 人工最终结论优先于机器结论；策略重跑不得覆盖人工结论；
- 重生成必须创建新 TTS Task 和新 AudioClip revision，旧 Clip、QA、失败和人工评价保留；
- ASR Provider 私有 DTO、凭据、endpoint、上传 URL 和原始响应不得进入通用 QA schema；
- ASR 或音频处理结果先进入任务临时区，经 schema、资源预算、文件和范围校验后提交；
- `submission_unknown` 不得自动重传可能计费或重复上传的请求；
- 仅审核备注变化不使 AudioClip 或章节消费者 stale；最终 approved → rejected 才传播到实际引用消费者；
- 未最终 approved 的活动 AudioClip 不得进入当前正式章节合成；
- 所有正式写入通过阶段 00 workflow/transaction 端口完成。

统一错误码至少包括：

```text
QA_INPUT_INVALID
QA_AUDIO_MISSING
QA_AUDIO_CORRUPT
QA_METRIC_UNAVAILABLE
QA_ASR_PROVIDER_UNAVAILABLE
QA_ASR_RESPONSE_INVALID
QA_ASR_SUBMISSION_UNKNOWN
QA_TEXT_DIFF_INVALID
QA_POLICY_UNRESOLVED
QA_RETRY_EXHAUSTED
QA_BASELINE_CHANGED
QA_REVIEW_REQUIRED
QA_STALE_SESSION
```

新增错误码必须先进入 contracts 测试，禁止 adapter、检查器、Core 和 UI 定义同义字符串。

## 8. 验收标准

- 每个当前正式 AudioClip 有机器检查记录和独立人工最终审核状态；
- 每个问题可定位到时间、spoken 文本或音频证据，并可回到正确上游阶段；
- ASR transcript、音频指标、机器结论和人工结论不会互相覆盖；
- 外部音频分析与相似度分支 complete；本地音频检查分支 not_applicable；VAD、diarization 按 M5-D01 最终启用结论具有明确 complete/not_applicable 记录；全部证据保留独立 provenance；
- 自动重试有限，失败和每个 AudioClip/QA revision 均保留；
- 策略/阈值升级产生新重评，不抹除旧结论；
- 未最终 approved 的片段不能进入当前章节合成；
- final approved→rejected 只使实际引用消费者 stale，仅备注不传播；
- Mock、live Provider、合成回归、真实人工试听和桌面交互证据分开报告。

## 9. 对 M6 的稳定交付

M5 必须向 M6 提供：

- immutable AudioClip revision 与活动指针、文件 artifact/hash、格式、时长、采样率和声道；
- immutable QAResult revision 与活动指针、目标 spoken revision、全部 QAIssue 和证据；
- 分离的 machineDecision 与 finalDecision、reviewer、review timestamp 和 policy/checker/threshold versions；
- 活动 QAPolicy/ThresholdProfile revision、选中能力分支、Provider/request/usage 和证据 provenance；
- 每次 regenerate 的旧 QA → remediation plan → 新 TTS Task/AudioClip → 新 pending QA Task 链接；
- 明确的合成 eligibility：只有活动 AudioClip + 活动 QAResult + `finalDecision=approved`；
- rejected/pending/stale/missing 片段及其 remediation target；
- `scriptUnitId`、顺序、精确依赖 selector、未解决 stale cause 和历史片段比较入口。

M6 不得根据 machineDecision、文件存在或历史 approved QA 推断当前片段可合成。
