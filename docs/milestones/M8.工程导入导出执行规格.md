权威顺序统一遵循 [无人值守执行协议第 2 节](../无人值守执行协议.md#2-权威顺序)；下列只是 M8 相关读取顺序：

6. 本文件的任务顺序、写入白名单和验证命令。

任何权利、容器、合并、编码或豁免冲突都必须停止并进入根待办，不得由执行模型推断许可或扩大范围。

## 2. 范围与非目标

### 2.1 M8 范围

- 生成版本化、可校验、不可变的工程配置包；
- 默认导出项目设置、角色/Alias/Stage、允许的 VoiceProfile metadata、发音词典、处理规则、结构 metadata、schema、迁移引用和来源指纹；
- 默认排除小说明文、corrected/script/spoken 文本、音频/BGM/SFX、缓存、密钥、令牌和绝对路径；
- 在 staging 中完成容器、路径、大小、schema、版本、checksum 和敏感字段校验；
- MVP 只支持“导入为新项目”，不覆盖当前项目；
- 对用户重新选择的合法小说生成重新绑定候选，并对歧义项进入人工确认；
- 恢复允许恢复的角色、音色 metadata、发音词典和处理配置；
- 发布前检查存在性、审核、stale、授权、章节顺序、总时长、时间轴和元数据；
- 通过可替换 release adapter 输出批准的成品格式和不可变发布快照；
- 保存 manifest、输入清单、adapter/参数、rights 结论、文件 hash 和历史快照。

### 2.2 非目标

- 不凭工程包恢复用户无权访问的小说、声音或模型资产；
- 不导出 Provider 密钥、明文令牌、模型权重或 Provider profile 私密配置；
- 不默认包含小说原文、派生明文、最终音频、BGM、SFX 或缓存；
- 不静默包含 `stale`、`missing`、`rejected`、未审核或未授权产物；
- 不覆盖、就地迁移或合并已有项目；
- 不把章节序号相同视为重新绑定成功；
- 不实现云同步、多人协作、市场、远程发布或 DRM；
- 不由 Renderer 读写容器、绝对路径、checksum 或项目数据库；
- MVP 不实现工程包加密；MP3/M4B 编码器与元数据兼容性仍以 M8-D04 的关闭证据为准。

## 3. 小模型执行协议

每次只领取一个任务 ID。开始前读取根 `AGENTS.md`、本文件第 1～6 节、任务输入、门禁证据和 `git status --short`。

执行规则：

- 先核对所有前置任务、schema/format version 和权利策略版本；
- 只修改任务卡列出的精确路径；
- 冻结安全/兼容夹具后，后续实现不得改 expected 来通过测试；
- 所有导出和导入先进入任务 staging/tmp，校验后再原子提交；
- 只使用已批准依赖；新增 archive、codec 或 metadata 依赖必须由门禁明确批准；
- 不修改上位计划、ADR、`docs/ideas/`、其他里程碑规格或根待办；
- 不暂存、提交、重置、删除用户数据或对仓库批量格式化；
- Mock、schema 和静态测试不得报告为跨设备恢复或播放器兼容已验证。

任务结束前运行 `git diff --check`、`git status --short`，并报告任务、结果、修改文件、命令/退出码、未验证项、既有改动和阻塞。

## 4. 公共不变量

- 工程包和发布输出都是不可变 `ExportSnapshot`；新导出不得覆盖旧快照或同名文件；
- manifest 必须记录 format/schema version、snapshot/project、来源指纹、包含能力、rights、artifact 清单、checksums、创建信息和处理器版本；
- 工程包与发布 manifest 必须记录 M8-D05 关闭时固定的 unsigned policy ID/version，不定义或调用 manifest 签名能力；
- 工程包默认拒绝小说/派生文本明文、音频、密钥、令牌、绝对路径、临时目录和未授权二进制；
- Character/Voice/Pronunciation/Script/Timeline 只能导出明确定义的 metadata 投影，不能直接序列化数据库行或领域对象全集；
- VoiceProfile/Embedding/微调结果按 rights 记录和 M8-D02 决定，不能按扩展名推断可导出；
- 所有容器条目先规范化并验证根目录包含、重复名、绝对路径、`..`、符号链接/等价链接、单条/总大小和解压比例预算；
- checksum、schema 和 rights 校验必须在导入提交前完成；失败包不得产生半项目；
- 未知 format 主版本拒绝；迁移只对 staging 中的副本生成新状态和迁移记录，不改原包；
- 导入默认创建新项目；除非 M8-D03 明确批准，任何已有项目合并都必须拒绝；
- 重新绑定使用来源指纹、内容 hash、标题、顺序、稳定块和证据评分；歧义保持 `unbound/missing` 并进入 review；
- 发布只引用明确 revision；当前缺失、未批准、拒绝、未授权或未豁免 stale 项必须阻断；
- 显式豁免若获批准，必须绑定新发布快照、具体 artifact/revision、理由、操作者和时间，不修改原 validity；
- 失败、取消和重启不损坏源项目、导入目标或既有快照；
- Renderer 只获得逻辑 ID、展示信息和用户选择结果，不能传任意输出绝对路径或可执行参数；
- 相同显式输入清单、版本和参数产生相同输入指纹；时间戳/snapshot ID 等非内容字段必须在契约中区分；
- 所有敏感性、授权和兼容结论均需证据；信息不足时阻断，不能默认允许。

统一错误码至少包括：

## 5. Decision Gates

### M8-G00：M0～M7 输入门禁

状态：`open`，阻塞 M8-01A 及以后任务。

未关闭时仍可执行：M8-00。

关闭条件：

- M0 的项目创建、只读/写 session、Artifact/Revision/Dependency、ExportSnapshot、迁移、恢复和临时文件提交已验证；
- M2～M5 已交付可版本化的角色、音色 metadata、发音、ScriptUnit、AudioClip 和 QA 状态；
- M6 已交付当前章节音频、assembly manifest 和 Clip 反向映射；
- M7 已交付当前 JSON timeline、WebVTT/SRT 派生物和完整依赖；
- rights/许可记录能对每个候选资产给出允许、禁止或需人工确认状态；
- Desktop 文件/目录选择、Core 传输、项目 session 和 `exports/` 不可变快照基础已验证；
- `pnpm run check` 通过。

M8-00 可在门禁打开时执行只读审计；不得自行标记上游完成。

状态：`open`，引用 [TODO-M8-01](../../todoe-check.md#todo-m8-01)，直接阻塞 M8-02、M8-07、M8-X01A 和 M8-30；M8-X01B、M8-09、M8-11 等后继以任务卡前置和 DAG 推导。

- SHA-256 checksum 的覆盖范围以及 payload entries、manifest、checksum 的写入顺序；哈希算法复用阶段 00 已固定的全局内容哈希，不新建同义算法。

执行模型不得自行选择 ZIP 实现、压缩 profile 或解析依赖，也不得实现自定义密码学。

- Character、Alias、Stage、允许的 VoiceProfile metadata、发音词典和处理规则可恢复；
- 导入失败不修改源项目、包或已有项目；
- 发布不静默包含 missing/rejected/pending/unlicensed/stale；
- 至少一个批准的 MP3/M4B 成品格式通过目标播放器兼容基准；WAV 只可作为附加格式，除非先重新确认 TODO-M8-04 方案 B；
- 工程包和发布输出可追溯到输入、revision、策略、adapter、rights 和 hash；
- 历史快照和同名输出不覆盖，失败/取消/重启可恢复或明确回滚。

## 9. 对 MVP 验收的稳定交付

M8 向阶段 90 交付：

- immutable 工程包 `ExportSnapshot`、format/schema version、rights/checksum/artifact manifests；
- 导入 inspection、迁移、重新绑定候选/人工决策和新项目创建记录；
- restored capability 清单、unbound/missing/conflict 报告；
- immutable release snapshot、章节/全书输入清单、format profile、adapter/version/parameters；
- 发布成品、metadata、文件 hash、unsigned policy、豁免结论和兼容证据；
- 工程包/发布的精确 stale cause、历史 revision 和失败恢复记录。

不得交付凭据、私钥、绝对路径、未授权素材、Renderer 临时状态或未经确认的重新绑定。
