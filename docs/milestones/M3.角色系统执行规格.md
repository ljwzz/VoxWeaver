## 1. 文档定位

本规格把 M3 拆成可单独实现、测试和交接的任务卡，不替代上位计划。权威顺序统一遵循 [无人值守执行协议第 2 节](../无人值守执行协议.md#2-权威顺序)；下列只是 M3 相关读取顺序：

1. `项目计划.md` 的范围、原则和 M3 完成定义；
2. `docs/spec/90.MVP联调与验收.md` 的里程碑映射；
3. 阶段 04、05 的领域要求；
4. 已接受 ADR 和已冻结 schema；
5. `docs/architecture/electron-desktop-architecture.md` 中与前述权威输入一致的辅助设计约束；
6. 本规格的执行顺序、文件白名单和验证命令。

发生冲突时停止当前任务并记录阻塞，不得由执行模型修改上位文档或代替负责人选择方案。

## 2. 范围与非目标

M3 复核并消费 M2 已交付的 Character Registry，不重复实现阶段 04。M3 的完成标志是：

- Character、Alias、CharacterStage、ScriptUnit speaker 和人工锁定均已通过 M2 正式契约交付；
- 核心角色跨章节引用稳定的 VoiceProfile revision；
- 普通角色可以从 VoicePool 获得可解释、可覆盖、可锁定的分配；
- 同一 Scene 的复用和冲突可以检测并进入人工审核；
- 每个正式 VoiceProfile 可追踪 Provider profile、dialect、模型、Voice ID、参数、参考资产、权利和质量状态；
- VoiceProfile revision 不可变，激活、回退和影响预览可追溯；
- 音色变化只使实际引用的 ScriptUnit 音频消费者过期，旧配置和旧产物保留。

M3 不包含：

- spoken、发音词典、批量 TTS、ASR、音频 QA、章节合成或时间轴；
- 真实 TTS Provider 请求、密钥、音频上传或正式生成；
- 自动声音克隆、模型下载、模型微调或本地推理；
- 把自动相似度、显示名或角色名直接作为身份结论；
- `docs/ideas/` 中未批准的关系图谱、完整人物时间线、声音素材工作台或其他候选能力。

## 3. 小模型执行协议

每次只领取一个任务 ID，一个任务只交付“单一结果”。执行模型必须：

1. 读取根 `AGENTS.md`、本规格第 2～5 节、当前任务卡及卡片列出的输入；
2. 运行 `git status --short`，记录已有 staged、modified 和 untracked 文件；
3. 核对全部前置任务与 Decision Gate 的关闭证据；
4. 只读取任务涉及的当前接口；目标符号不存在时才扩大只读搜索；
5. 只修改任务卡“允许写入”中的文件；共享 `src/index.ts`、`package.json` 和锁文件任务必须串行；
6. 先写失败测试或冻结夹具，再写最小实现；测试从构建后的 `dist` 导入；
7. 不新增未获批准的依赖、Provider、模型、阈值、字段或自动决策；
8. 不执行 git 暂存、提交、重置、清理、全仓格式化或状态文档升级；
9. 不把 Mock、文档或单包测试通过表述成 M3 完成。

任务结束前必须运行：

```bash
git diff --check
git status --short
```

交接格式：

```text
任务：M3-XX
结果：complete | blocked | failed | not_applicable
修改文件：逐项列出
验证：命令、退出码和关键断言
未验证：逐项列出
既有改动：是否保持不变
阻塞：Gate、TODO、错误文本或缺失输入
```

派发者提供的最小上下文包只包含：本规格第 2～5 节、单一卡片、已关闭门禁证据、卡片涉及的当前接口和开始时的 `git status`。

## 4. 公共不变量

- Character ID、VoiceProfile ID、Provider Voice ID 和显示名必须是独立字段；
- Character/Stage、ScriptUnit 瞬时表现和 VoiceProfile 默认参数不得互相覆盖；
- VoiceProfile revision、VoiceAsset revision 和 VoiceAssignment revision 提交后不可原地修改；
- 创建草稿 revision 不传播 stale；只有激活或绑定变化才按依赖传播；
- 人工锁定优先于 Stage 绑定、角色默认值、规则和模型候选；后台重跑不得覆盖锁定；
- 未通过权利和质量准入的 VoiceAsset 不得被正式 VoiceProfile 引用；
- 核心角色活动 VoiceProfile 不得被 VoicePool 自动分配给普通角色；
- 同一 Scene 不得静默复用同一 VoiceProfile revision；冲突必须输出证据和 review；
- 自动分配只能产生候选，正式激活必须保存来源、规则版本、操作者和基线 revision；
- Provider 私有 DTO、凭据、endpoint 和原始响应不得进入 Character、ScriptUnit 或通用 VoiceProfile schema；
- 任何影响计划必须输出明确 `scriptUnitIds` 或已批准的 ArtifactSelector，不得默认整书 stale；
- 仅显示名、备注、人工评价文字变化不得使音频消费者 stale；
- 旧 Profile、Assignment、试听评价、审核和已生成产物不得自动删除；
- 所有正式写入通过阶段 00 workflow/transaction 端口提交。

统一错误码至少包括：

```text
VOICE_PROFILE_INVALID
VOICE_PROFILE_REVISION_CONFLICT
VOICE_ASSET_RIGHTS_REQUIRED
VOICE_ASSET_QUALITY_REQUIRED
VOICE_ASSIGNMENT_UNRESOLVED
VOICE_ASSIGNMENT_LOCKED
VOICE_SCENE_CONFLICT
VOICE_BASELINE_CHANGED
VOICE_REVIEW_REQUIRED
```

新增错误码必须先进入 contracts 测试，禁止在 application、Core 或 Renderer 创建同义字符串。

## 8. 验收标准

- M2 的稳定 Character/Stage/ScriptUnit 输入未被复制或改写；
- 核心角色跨章节使用可追踪的稳定 VoiceProfile revision；
- 普通角色候选可解释、可修改、可锁定，同 Scene 冲突可复现；
- Profile、Asset、Assignment、审核和激活历史均可查询；
- 未通过授权、质量或人工阻断项的配置不能进入下游正式生成；
- Profile/Asset/Assignment 变化只传播到实际引用 ScriptUnit；
- 更换未来 TTS adapter 不改变 Character、ScriptUnit 或 VoiceProfile 通用契约；
- 测试、静态检查、桌面交互和真实素材/Provider 未验证项被明确分开报告。

## 9. 对 M4 的稳定交付

M3 必须向 M4 提供：

- immutable Character Registry、Alias、CharacterStage 和 ScriptUnit revision 引用；
- immutable VoiceProfile/VoiceAsset/VoiceAssignment revision 与活动指针；
- 每个 ScriptUnit 的解析结果、锁定、瞬时表现和未解决冲突；
- Provider profile/dialect/model/Voice ID 的引用，不包含凭据或厂商 DTO；
- 资产权利/质量准入结论和审核证据；
- 精确 `scriptUnitIds` 或已批准 selector、input fingerprint 和未解决 stale cause。

M4 不得把 M3 候选当作已激活分配，也不得绕过 rights/quality/review 阻断。
