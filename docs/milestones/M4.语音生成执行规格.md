## 1. 文档定位

本规格把 M4 拆成可单独实现、测试和交接的任务卡，不替代上位计划。权威顺序统一遵循 [无人值守执行协议第 2 节](../无人值守执行协议.md#2-权威顺序)；下列只是 M4 相关读取顺序：

1. `项目计划.md` 的产品范围、文本层次、Provider 边界和 M4 完成定义；
2. `docs/spec/90.MVP联调与验收.md` 的 M4 映射；
3. 阶段 06、07 的领域要求；
4. `docs/adr/0001-model-capabilities-via-provider-apis.md`；
5. 已冻结 schema；
6. `docs/architecture/electron-desktop-architecture.md` 中与前述权威输入一致的辅助设计约束；
7. 本规格的任务顺序、白名单和验证命令。

冲突时停止当前任务并记录阻塞。执行模型不得修改上位文档、ADR、Decision TODO 或已冻结 schema。

## 2. 范围与非目标

M4 的完成标志：

- 每个已审核 ScriptUnit 从 corrected 产生独立、可审核、可定位的 spoken revision；
- 数字、日期、单位、英文、缩写、专名、多音字和人工词条以版本化处理链产生候选；
- corrected、spoken 和发音表示可双向定位，人工锁定优先；
- PronunciationEntry 变化只使实际命中的 SpokenUnit 及其音频消费者过期；
- 每个满足输入门禁的 ScriptUnit 可以通过统一 TTS port 独立生成、缓存、取消和有限重试；
- TTS 结果先进入任务临时区，经 schema、资源预算、音频规格和 hash 校验后提交 immutable AudioClip revision；
- 相同完整输入指纹可以复用历史成功结果，不同 spoken、音色、参数、Provider 或输出规格不得误命中；
- Provider 中断、异步恢复和未知提交状态可判定，不覆盖旧音频。

M4 不包含：

- ASR、音频 QA、机器/人工最终质量结论、章节合成或时间轴；
- 修改 corrected、Character、VoiceProfile 或 ScriptUnit 的上游事实；
- 整章一次生成、无限重试或失败时覆盖旧 AudioClip；
- 内置、下载、加载、托管或启动 TTS/G2P 模型；
- 让 Renderer 直接访问 Provider、凭据、项目绝对路径或二进制正式文件；
- 把 SSML、PLS、拼音、音素或任一厂商 hint 自动选为通用领域真值；
- `docs/ideas/` 中未批准的声音微调、复杂后期或素材工作台。

## 3. 小模型执行协议

每次只执行一个任务 ID，一个任务只产生一个可验证结果。

开始前：

1. 读取根 `AGENTS.md`、本规格第 2～5 节、当前卡片及其输入文档；
2. 运行 `git status --short` 并记录既有改动；
3. 核对前置任务、M3 稳定交付和全部相关 Gate；
4. 只读取卡片列出的包和当前接口；找不到符号时才扩大只读搜索；
5. 确认卡片写入文件未被其他改动占用。

执行中：

- 只修改“允许写入”文件；共享 index、package manifest 和 lockfile 的卡片串行；
- 先写失败测试或冻结夹具，再写最小实现；测试从 `dist` 导入；
- schema、Prompt、处理器、词典、策略、adapter 和输入指纹显式版本化；
- 默认自动测试只使用 deterministic fake/mock，不发真实网络请求；
- 新依赖、Provider、输出格式、阈值或降级行为没有关闭 Gate 时立即停止；
- 不执行 git 暂存、提交、重置、清理或全仓自动修复；
- 不把 Mock、单包测试、live smoke 或文档检查表述为整个 M4 完成。

结束前：

```bash
git diff --check
git status --short
```

交接格式：

```text
任务：M4-XX
结果：complete | blocked | failed | not_applicable
修改文件：逐项列出
验证：命令、退出码和关键断言
Provider：none | mock | live-approved
外部数据：none | synthetic | approved-project-data
未验证：逐项列出
既有改动：是否保持不变
阻塞：Gate、TODO、错误文本或缺失输入
```

## 4. 公共不变量

- `corrected`、ScriptUnit 和 M3 VoiceProfile/Assignment revision 不可被 M4 原地修改；
- `spoken` 是独立正式层，不在 corrected 中插入厂商控制标记；
- 通用 `spokenText` 必须可人工阅读；厂商 SSML、音素表或 engine hint 只存在于 adapter 映射或版本化 hint 字段；
- 文本范围沿用 M1/M2 冻结的 revision-aware 半开区间，不定义第二套 offset；
- 每个词典命中、规则替换和 G2P 候选保留来源、范围、处理器/词典版本和审核状态；
- ScriptUnit 人工锁定和词典人工锁定优先于规则、模型和 Provider 默认；
- 无法可靠确定的发音必须进入 review，不得伪造高置信度；
- TTS 最小正式生成单位是 ScriptUnit；批量操作只编排多个独立任务；
- CanonicalTtsRequest 不含厂商私有 DTO，业务层不得根据 adapter ID 编写厂商分支；
- 缓存键必须覆盖 spoken 内容/revision、VoiceProfile revision、Stage/瞬时表现、发音提示、Provider profile/dialect/model/adapter、参数、seed policy、数据策略和 AudioOutputSpec；
- Provider 输出先写 `tmp/<task-id>/`，完整校验后才能提交正式 AudioClip revision；
- `AbortSignal` 只表示停止本地等待；远端取消能力必须由 adapter 显式声明；
- `submission_unknown` 不得自动重提可能计费或非幂等请求；
- 重试只适用于已批准的 retryable 分类且有上限；参数、文本和权限错误不得盲重试；
- 旧 SpokenUnit、请求、原始响应审计、AudioClip、失败记录和缓存命中证据不得自动删除；
- 所有正式写入通过阶段 00 workflow/transaction 端口完成。

统一错误码至少包括：

```text
PRONUNCIATION_INPUT_INVALID
PRONUNCIATION_REVIEW_REQUIRED
PRONUNCIATION_HINT_UNSUPPORTED
SPOKEN_BASELINE_CHANGED
SPOKEN_ALIGNMENT_INVALID
TTS_INPUT_NOT_APPROVED
TTS_CAPABILITY_UNSUPPORTED
TTS_PROVIDER_UNAVAILABLE
TTS_RESPONSE_INVALID
TTS_OUTPUT_INVALID
TTS_SUBMISSION_UNKNOWN
TTS_RETRY_EXHAUSTED
TTS_STALE_SESSION
```

新增错误码必须先进入 contracts 测试，不得在 adapter、Core 或 UI 创建同义字符串。

## 8. 验收标准

- 每个正式 ScriptUnit 有可审核 spoken，corrected/spoken/发音表示可互相定位；
- 人工锁定和词条范围行为稳定，未命中变化不传播 stale；
- 每个通过输入门禁的 ScriptUnit 可独立生成、缓存、取消、重试和恢复；
- 活动执行策略 revision 可查询；集合生成受版本化并发、限流、预算、队列容量和租约控制；
- Provider 参考资产按选中分支保留创建、引用、撤销、删除和失败恢复历史；
- 每个 AudioClip 可追踪全部输入、Provider/adapter、模型、音色、参数、输出规格、请求和 hash；
- 相同完整指纹复用历史成功结果，不同输入不误用；
- 失败、中断和未知提交不破坏其他片段或旧 revision；
- Provider 替换不改变通用领域契约，Renderer 不访问 Provider 或凭据；
- 测试、Mock、live Provider、桌面交互和未执行验证明确分开。

## 9. 对 M5 的稳定交付

M4 必须向 M5 提供：

- immutable SpokenUnit revision、spokenText、发音表示、alignment、词条命中和人工锁定；
- immutable AudioClip revision，含 scriptUnitId、输入指纹、文件 artifact/hash、格式、时长、采样率、声道和生成状态；
- Provider profile/dialect/model/adapter/request/job、参数、Seed 策略、usage 和恢复记录；
- 活动 TTS 执行策略 revision、队列/租约/预算快照，以及 Provider 参考资产生命周期记录；
- AudioClip 活动指针、历史失败/重试/取消记录和未解决 stale cause；
- 精确 `scriptUnitIds` 和 M2/M3/M4 输入 revision 依赖。

M4 只把新片段标为“待 QA”，不得写入机器通过或人工批准结论。
