## 2. M2 边界

M2 的完成标志：

- `normalized` 可以产生可审计、可撤销的 `corrected` revision；
- 校对规则和 LLM 只产生结构化 proposal，不直接重写整章；
- `corrected` 可以产生有稳定 ID、来源范围、类型和证据的 `ScriptUnit`；
- 项目具有唯一 Character Registry；
- Character、Alias、CharacterStage 和说话人解析可审核、可追溯；
- 无法可靠确定的说话人保持 `unknown`；
- 修改一个块、别名或角色范围时，只重处理实际相交的 ScriptUnit 和消费者；
- 模型建议与人工最终决定分别保存。

M2 不包含：

- VoiceProfile、VoicePool、音色分配或声音素材；
- `spoken`、发音词典、TTS、ASR、音频 QA、合成或时间轴；
- 角色关系图谱、完整人物时间线及 `docs/ideas/` 中未批准能力；
- 内置、下载、启动或管理 LLM；
- Renderer 直接调用 Provider；
- 未经批准的模型、阈值、Provider dialect 或自动应用策略。

阶段 04 同时为 M3 提供输入。M2 只交付角色身份、别名、长期阶段和说话人解析，不提前实现阶段 05。

## 3. 小模型执行与无人值守派发协议

### 3.1 任务状态与派发

每次只领取一个任务 ID，一个任务只交付一个可验证结果。任务只使用以下状态：

| 状态 | 含义 |
|---|---|
| `pending` | 前置未核对或尚未派发 |
| `ready` | 前置、文件占用和全部 Gate 均满足 |
| `in_progress` | 已由一个执行者领取 |
| `complete` | 单一结果和全部必测项均有证据 |
| `blocked` | 缺决策、依赖、环境或上游契约 |
| `failed` | 实现或验证失败且已记录证据 |
| `not_applicable` | 已关闭的条件分支明确排除该任务 |

禁止使用 `done`、`skip` 或 `mostly_complete` 等同义状态。文件头的“当前门禁”只摘要 G00；实际派发必须同时核对第 5 节全部 Gate、任务卡前置、DAG 和文件占用。Gate 打开时，“未关闭时仍可执行”是唯一派发白名单，不得以阻塞列表的补集扩大派发范围。

第 5 节是 M2 决策的唯一执行入口。候选策略已确认只代表产品方向冻结，不补全 Provider/runtime profile、参数、ADR 或 live 证据，也不自动关闭 Gate。执行模型不得重选候选项、代填缺失值或修改 Gate 状态。单一分支被阻塞时继续派发其他无依赖分支；白名单耗尽后输出阻塞清单、已完成证据和下一可执行任务。

### 3.2 最小上下文与开始检查

派发者只提供：根 `AGENTS.md`；本文件第 2～5 节；当前单一任务卡；已关闭 Gate 证据；相关当前接口/schema；开始时的 `git status --short`；文件占用与并发所有者。不得一次附带 M2 全部源码、所有 Prompt 或未批准候选实现。

开始前必须依次：

1. 读取最小上下文包；
2. 运行 `git status --short`，记录 staged、modified 和 untracked 文件；
3. 核对前置、M0/M1 证据、Gate、DAG 和条件分支；
4. 确认“允许写入”文件未被其他任务占用；
5. 记录输入文件和 baseline revision/hash；
6. 先运行最窄的既有测试。基线已失败时记录关联性，不顺手修复无关失败。

### 3.3 写入、并发与停止边界

- 只修改任务卡“允许写入”列出的文件；一个可写文件同时只属于一个任务。
- 共享 `src/index.ts`、`package.json`、锁文件、公共 schema 或路由的任务串行；并行任务只共享只读输入和冻结夹具。
- 目录通配只能用于任务卡明确授权的新包骨架、固定夹具或单一 Renderer feature；文件占用只在验证和交接完成后释放。
- 后完成的任务不得覆盖先完成任务的接口；发现接口漂移时立即停止，重新审计前置、基线 revision/hash 和文件占用。
- 测试放在目标包 `test/*.test.mjs`，从构建后的 `dist` 导入；先写失败夹具或测试，再写最小实现。
- Prompt、schema、处理器和缓存键显式版本化；Provider 输出在进入领域逻辑前必须再次执行本地 schema 与范围校验。
- 不修改上位计划、阶段文档、ADR、冻结 schema/fixture/expected/Prompt 或 `docs/ideas/`，除非任务卡显式授权。
- 不新增未批准依赖、Provider、模型、阈值、外部服务或自动应用策略；需要时立即以 `blocked` 停止。
- 不执行 git 暂存、提交、重置、用户文件清理或全仓自动修复；不覆盖既有改动。
- 验收卡不得修改实现、测试预期、夹具、Prompt 或 schema；Mock 不得证明 live Provider 路径通过。

### 3.4 验证与交接

证据分层：L1 目标模块/纯函数测试；L2 目标 package build/typecheck/test；L3 跨 package integration test；L4 `pnpm run check`；L5 桌面交互、live Provider 或真实样本。L1～L4 不替代 L5，环境或授权缺失时必须记为未验证。任务结束前运行：

```bash
git diff --check
git status --short
```

交接必须使用：

```text
任务：M2-XX
结果：complete | blocked | failed | not_applicable
修改文件：逐项列出
验证层级：L1～L5
验证：命令、退出码和关键结果
模型调用：none | mock | live-approved
输入基线：revision/hash
未验证：逐项列出
既有改动：是否保持不变
阻塞：Gate、错误文本或缺失输入
下一可执行任务：只列前置已满足的 ID
```

只有单一结果和全部必测项都有证据才能标记任务 `complete`。只有所有必需任务 complete、条件任务 complete/not_applicable、全部 Gate closed、冻结夹具 hash 未变、L1～L4 通过且必需 L5 有独立证据时，负责人才能在独立变更中确认里程碑完成。

## 4. 公共不变量

所有任务共同遵守：

- `normalized`、`canonical`、raw 和 SourceAsset 不可覆盖；
- 任何应用操作都必须基于明确的基线 revision/hash，基线变化时拒绝盲写；
- `CorrectionProposal`、`ScriptUnit`、Character/Alias/Stage 都有稳定 ID、证据和审核状态；
- LLM 只返回候选、分类、范围、证据和置信度，程序负责校验、diff、应用和持久化；
- Provider adapter 不打开状态库、不激活 revision、不删除 Artifact；
- 非法 JSON、未知 schema 主版本、越界范围、整章替换和未知枚举不得进入正式产物；
- 人工锁定优先于规则和模型，后台重跑不得覆盖人工决定；
- `unknown` 是合法结果，不为满足 schema 随机选择角色；
- Character 长期阶段与 ScriptUnit 瞬时情绪、身体状态和表达方式分离；
- 角色显示名变化不得改变 Character ID；同名不得自动合并；
- Review 备注变化不得使内容消费者 stale；
- 旧 revision、拒绝记录、合并/拆分历史和模型原始响应审计不得自动删除；
- 所有正式写入通过阶段 00 的 workflow/transaction 端口完成。

统一错误码至少包括：

```text
TEXT_BASELINE_CHANGED
TEXT_PROPOSAL_INVALID
TEXT_PROPOSAL_CONFLICT
LLM_PROVIDER_UNAVAILABLE
LLM_RESPONSE_INVALID
LLM_SUBMISSION_UNKNOWN
SCRIPT_OUTPUT_INVALID
SPEAKER_UNRESOLVED
CHARACTER_CONFLICT
CHARACTER_LOCKED
M2_REVIEW_REQUIRED
```

新增错误码必须先进入契约测试，禁止各阶段创建语义重复的字符串。

## 8. M2 对下游的稳定交付

M2 完成后必须向阶段 05～11提供：

- immutable corrected revision 及与 normalized/block/source 的映射；
- 稳定 ScriptUnit ID、顺序、文本、来源、类型、speaker、CharacterStage 引用和瞬时表现；
- Character Registry、Alias、Stage、证据、审核和历史；
- unknown/冲突/人工锁定状态；
- 精确依赖 selector、input fingerprint、processor/prompt/schema version；
- 局部变化影响的 scriptUnitIds 和未解决 stale cause。

不得向下游暴露 Provider 私有 DTO、凭据、Renderer 临时状态或未审核模型原始结论。
