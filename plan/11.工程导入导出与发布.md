# 阶段 11：工程导入导出与发布

状态：`planned`
实现审计：`unverified`
前置阶段：[00 项目基线与工程工作区](./00.项目基线与工程工作区.md) 及需要导出的业务阶段

## 1. 目标

定义可版本化、可校验、可迁移的 VoxWeaver 工程包和发布快照，使项目可以跨设备恢复配置、重新绑定合法小说，并输出可追溯的章节或全书成品。

## 2. 范围

- 工程包 manifest 和格式版本；
- 项目配置、角色、音色、发音、剧本 metadata、时间轴和处理规则导出；
- 默认排除小说原文、最终音频、BGM、SFX 和缓存；
- 工程导入、schema 校验、迁移和小说重新绑定；
- 文本哈希、章节和稳定 ID 辅助匹配；
- WAV/MP3/M4B 等发布适配器及元数据；
- 发布前有效性、审核、授权和完整性检查；
- 导出清单、文件哈希和快照。

## 3. 非目标

- 不承诺仅凭工程包恢复无权访问的小说或声音素材；
- 不把购买、订阅或可访问素材视为已获得复制、克隆、训练或发布许可；
- 不在 MVP 实现云同步、多人协作或模型市场；
- 不默认导出模型权重或密钥；
- 不静默包含 stale、missing、rejected 或未授权产物。

## 4. 工程包结构

候选扩展名：`.audiobook-project`。容器可以采用 ZIP + JSON，但必须由 ADR 确认并版本化。

```text
project-package/
├── manifest.json
├── project.json
├── schemas/
├── characters/
├── voices/
├── pronunciation/
├── scripts/metadata/
├── timelines/metadata/
├── processing-rules/
├── migrations/
└── checksums.json
```

manifest 至少记录：

```text
format_version
project_id / exported_snapshot_id
created_at / created_by
included_capabilities
required_schema_versions
source_fingerprints
artifact_manifest
rights_manifest
checksums
```

所有 JSON 契约采用明确的 JSON Schema 版本：

https://json-schema.org/specification

## 5. 默认包含与排除

默认包含：

- 项目设置和处理策略；
- Character、Alias、CharacterStage；
- VoiceProfile metadata 和允许导出的配置；
- 发音词典；
- Prompt/处理器版本引用；
- Scene、Script 和 Timeline metadata；
- schema、迁移和来源指纹。

默认排除：

- 小说原文、raw、canonical、normalized、corrected、spoken 明文；
- 最终及缓存音频；
- BGM、SFX 和原生声音素材；
- 密钥、访问令牌、绝对本地路径；
- 许可不允许再分发的 Embedding、微调权重或模型。

VoiceProfile、Embedding 和微调结果是否可导出必须由各资产的权利和许可记录决定，不能仅按文件类型判断。

## 6. 工程导入和重新绑定

```text
选择工程包
→ 容器和 checksum 校验
→ schema/version 检查
→ 必要迁移预览
→ 创建新项目或受控合并
→ 用户重新选择合法小说/声音资产
→ 计算 source fingerprint 和章节匹配候选
→ 人工确认不确定映射
→ 恢复配置并重新计算有效性
```

导入不得直接覆盖已有项目。合并必须有独立设计和显式确认；MVP 可以只支持“导入为新项目”。

重新绑定不能只按章节序号匹配，应组合内容哈希、标题、顺序、稳定块和人工确认。未匹配内容保持 `missing` 或 `unbound`，不得强行关联。

## 7. 发布快照

发布前必须检查：

- 所有引用产物存在；
- 需要发布的 AudioClip 和章节已审核；
- 不包含未豁免 stale 产物；
- 项目素材和声音资产满足当前发布范围；
- 章节顺序、总时长、时间轴和元数据一致；
- 导出适配器版本、参数和输出哈希已记录。

如允许显式豁免 stale 项，必须新建发布快照，列出每个豁免原因；原产物仍保持 stale。

## 8. 页面

- 工程包包含项预览和敏感资产提示；
- 目标目录和冲突校验；
- 导入 schema、迁移和重新绑定报告；
- 匹配候选人工确认；
- 发布前完整性、审核、授权和 stale 检查；
- 导出进度、失败恢复和输出清单；
- 历史导出快照和校验结果。

## 9. 版本和过期影响

- 工程包是不可变快照，不跟随源项目自动变化；
- 项目新 revision 不修改旧工程包；
- 章节顺序、元数据、时间轴或章节音频变化只使依赖它们的发布快照过期；
- 封面变化不使剧本和章节音频过期；
- schema 迁移生成新项目状态和迁移记录，不重写原工程包；
- 历史发布文件不能被同名覆盖。

## 10. 早期实现迁移

检查旧功能是否：

- 工程包无格式和 schema 版本；
- 包含绝对本地路径、密钥或未授权素材；
- 只按章节序号重新绑定；
- 导入直接覆盖当前项目；
- 不校验 checksum；
- 发布静默包含 stale/未审核片段；
- 导出同名覆盖旧版本；
- 无迁移和失败恢复。

旧包格式应先编写只读 importer 和迁移夹具；无法确认来源的资产不得自动进入正式活动版本。

## 11. 测试要求

- 包结构、schema、checksum 和未知字段；
- 版本兼容、迁移失败和只读检查；
- 默认排除小说和音频明文；
- 不导出密钥和绝对路径；
- 重新绑定的完全匹配、部分匹配和冲突；
- 导入为新项目不覆盖现有数据；
- stale、missing、rejected 和未授权阻断；
- 发布快照不可变及历史输出不覆盖。

## 12. 验收标准

- 工程配置可导出并在新项目中导入；
- 默认工程包不包含小说原文和最终生成音频；
- 用户可以重新绑定小说并人工处理不确定映射；
- 角色、音色 metadata、发音词典和处理规则可恢复；
- 当前正式发布不静默包含 stale 或未审核产物；
- 导出物可追溯到项目、revision、适配器和输入清单；
- 失败不会损坏源项目或既有快照。

- MP3/M4B 元数据和播放器兼容基准；
- 显式 stale 豁免政策；
- 工程包签名和来源验证；
- 大型发布文件的断点和校验策略。
